# shared/ — 서버·화면 공용 코드

## 맡은 일
서버와 두 화면이 함께 쓰는 것: 타입과 스키마(`types.ts`), 결과 문구(`result-language.ts`), 한국 달력 날짜(`dates.ts`), 시·도 코드(`jurisdictions.ts`), 연결 목록(`connection-catalog.ts`), 검증 상태 표현(`verification.ts`), 접수·공공 API·근거 묶음 공용 타입, 정보 고지문(`information-notice.ts`).

## 맡지 않는 일
- `server/`, `src/`, `beta/` 어느 쪽도 가져오지 않는다. 의존 방향은 서버·화면 → `shared/` 한 방향이다.
- Node 전용 API(파일, 프로세스, 네트워크)와 브라우저 전용 API(DOM)를 쓰지 않는다. 양쪽에서 돌아야 한다.
- 비즈니스 규칙의 실행(승인, 빈틈 계산)은 서버에 있다. 여기에는 형태와 문구만 둔다.

## 반드시 지키는 것
- 결과에 보이는 단정 문구는 `result-language.ts`에서만 만든다. 화면이 "위험", "위반" 같은 문구를 따로 만들지 않는다. 필수 표시 "검토 후보 — 법적 판단 아님, 베타"를 빼는 경로를 만들지 않는다.
- 쟁점 분류는 `clear_risk` / `human_review` / `more_data` 세 값뿐이다.
- 날짜는 한국 달력(`koreaDate`)으로 계산한다. `new Date()`의 현재 시각을 직접 쓰지 않는다.
- 연결 목록(`connection-catalog.ts`)은 코드 기준 법제처 인증값 1개 + 서비스 28개다. 목록을 바꾸면 화면 안내와 키 입력 경로를 함께 확인한다.
- 타입을 바꾸면 서버와 두 화면이 모두 빌드되어야 한다. 화면 잠금 대상 파일이 이 타입을 가져오므로, 화면 파일을 바꿔야 하면 사용자 승인과 재잠금이 필요하다.

## 구현 방식
- zod 스키마로 형태와 검증을 한곳에 둔다. 서버가 요청을 검증할 때 같은 스키마를 쓴다.
- 부수 효과 없는 순수 함수로 유지한다.

## 시험
- 문구·날짜·시·도 코드는 단위 시험으로 고정한다. 날짜는 한국 시간 자정 경계(UTC 15시)를 확인한다.
