# A07 호출 안정화 및 실측

UI·UX는 변경하지 않았다. 기존 공통 HTTP 제한은 20초, 자동 재시도 없음이었다. 보편적으로 정해진 단일 시간 제한은 없으며 이 앱의 선택값이다.

## 적용 정책

- A07 공식 endpoint에만 요청당 60초(응답 본문 수신 포함), 최대 2회(최초+1회 재시도).
- 네트워크·시간 초과·HTTP 500/502/503/504·기관 오류코드 01/05만 제한적으로 재시도. 5~7초 대기, Retry-After가 더 길면 그 값을 존중. 30초 넘는 재시도 지시는 대기 상태로 두며 즉시 재시도하지 않음.
- A07 연결 확인과 검색이 같은 직렬 호출 경로를 사용. 응답 완료 후 최소 2초 간격, 같은 진행 중 요청은 합침. 대기 포함 4개까지만 수용, 대기 180초 초과 시 추가 호출하지 않음.
- 429는 최소 60초 또는 Retry-After까지 재호출 유예. 기관 일일 한도 코드22는 다음 한국 날짜까지, 초당 제한 코드23은 최소60초 유예. 실제 기관 초기화 시점은 계정 정책 확인 필요.
- 인증·권한·차단·만료(20/29/30/31)는 재시도하지 않음. 새 키는 별도 상태로 분리. 같은 키는 5분간 추가 호출 유예.
- 3개 연속 요청이 제한된 재시도 후에도 실패하면 5분간 호출 중단. 실패를 정상 0건으로 바꾸지 않음.
- 최근 50개 요청의 총 소요시간·시도 횟수·시도별 소요시간·고정 오류 분류를 메모리에 기록. 키·검색어·인증 URL·기관 원문 오류 메시지는 기록하지 않음.
- 호출 대기·차단 상태와 중복 합침은 단일 서버 프로세스 범위. 다른 프로그램이 같은 키를 사용하는 호출량이나 서버 재시작 전의 한도를 합산 관리하는 기능은 아직 없음. 계정 잔여량을 임의 추정하지 않음.
- 다른 API는 기존 20초 정책 유지. 기관의 장애·차단 가능성 0% 보장이나 API 키 만료 연장을 의미하지 않음.

- 최신 코드 `npm run check`: 21개 테스트 파일, 235개 테스트 통과.
- A07 전용 시험8개: 긴 대기 정책, 한정 재시도, 한도/인증 중단, 동일 요청 합침, 직렬화, 연속 실패 차단·복구, 긴 Retry-After, 대기열 제한, HTTP200 내부 한도 오류 등을 검증.

- 운영 반영: 기존 앱의 정상 종료 API 사용(진행 중 검토 없음), 기존 `.local`로 숨김 실행. 2026-10-08 18:42:59 한국시간 운영 `/api/public-apis/waste-companies/probe`가 약0.957초에 정상1건을 반환했다. `work/a07-production-probe.json`에 기록했다.
- 4317 HTTP200, 기존 `index-BivsNquf.js` 제공, 작업 전후 `src` 및 `dist` 파일 해시 동일. watchdog 및 정기 접속 확인은 재개하지 않았다.
