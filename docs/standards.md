# 지켜야 할 규칙

어기면 빌드·시험이 깨지거나, 개인 자료가 새거나, 법적 오해를 부르는 것만 적는다.

## 검증 관문

- 실질적인 변경 뒤에는 `npm run check`(타입 검사 + 서버 빌드 + 화면 빌드 + 전체 시험)를 통과시킨다. 서버를 띄우는 E2E(`npm run test:e2e*`)는 반드시 격리된 `SHE_DATA_DIR`로 돌린다. 사용자의 실제 `.local` 데이터에 붙이지 않는다.
- 건너뛴 시험과 외부 서비스에 의존하는 시험은 결과 보고에서 따로 적는다. 통과로 합치지 않는다.
- CI: PR은 Linux, main은 Linux + Windows. Windows 작업은 시간 초과가 간헐적으로 난다. 실패한 작업만 다시 돌리고 코드 문제로 단정하지 않는다.
- 날짜에 민감한 변경(기준일, 24시간 규칙, 시행일)은 수동 날짜 행렬 워크플로(`date-matrix.yml`)로도 확인한다.
- 워크플로가 쓰는 외부 액션은 태그가 아니라 커밋 해시로 고정한다.

## 검토 판단의 구조

- 기본 경로에서 `clear_risk` 분류를 새로 만드는 코드를 추가하지 않는다. 추가가 필요하면 사용자 결정을 먼저 받는다. 모델 출력은 반드시 인용 검증·분류 하향 함수(`legal.ts`의 `enforceIssue`)를 거친 뒤에만 `reviews.ts`에서 저장한다. 이 함수를 건너뛰는 저장 경로를 만들지 않는다.
- 인용 검증, 근거 빈틈, 확정 답변 판정을 바꾸면 해당 단위 시험(`legal.test.ts`, `reviews.test.ts`, `fact-provenance.test.ts`)을 같이 바꾸고, `clear_risk`가 나오지 않는 것을 확인하는 시험을 유지한다.
- 결과를 화면에 보여주는 문구는 `shared/result-language.ts`를 거친다. 화면이 따로 "위험", "위반" 같은 단정 문구를 만들지 않는다.

## 모듈 경계

- `shared/`는 서버·화면이 함께 쓰는 타입, 문구, 날짜, 지역 코드만 둔다. `shared/`에서 `server/`나 화면 파일을 가져오지 않는다.
- 화면(`src/`, `beta/`)은 서버 코드를 가져오지 않는다. 서버와는 HTTP로만 통신한다(서버가 내보내는 타입 파일 `beta-contract`만 예외로 양쪽이 같이 쓴다).
- 후보 계층(2~7단계의 `*-v2`~`*-v7` 파일)을 기본 앱 경로에서 가져오거나 연결하지 않는다. `createApp`은 시험에서 가짜 사용자를 줄 때만 연결한다.
- 외부 호스트로 나가는 새 호출을 추가하면 그 호스트를 허용 목록에 넣고 시험을 같이 추가한다. 허용 목록 밖으로 우회하는 모듈(`net`/`tls` 직접 사용, 다른 HTTP 클라이언트)을 쓰지 않는다.
- 사용자 데이터를 저장하는 새 표를 만들면 암호화 대상(밀봉 표) 포함 여부를 정하고, 포함하지 않는다면 이유를 코드 주석에 남긴다.

## 화면 잠금

- 옛 화면 29개 파일과 베타 화면(`beta/`, `dist-beta/`, 베타 빌드 설정, `beta-contract`)은 잠금 목록(`docs/implementation-v8/ui-freeze-v8.json`)에 SHA256 해시로 묶여 있다. 목록의 파일이 하나라도 바뀌면 시험 `v8-ui-freeze`가 실패한다.
- 바꿔야 하면 **사용자 승인을 받은 뒤** 파일을 고치고, `node scripts/freeze-ui-v8.mjs`로 목록을 새로 만든다. 이 스크립트는 승인 없이 돌리지 않는다.
- 잠금을 풀고 다시 묶어도 기능은 그대로 작동해야 한다. 화면 변경 뒤에는 베타 E2E(`scripts/e2e-beta-v8.mjs`)와 빌드 시험(`v8-beta-build`)을 통과시킨다.
- 화면 변경 없이 서버만 바꾸는 일(신뢰성, 근거 조사, 설계 문서)은 잠금과 무관하게 한다.
- **`beta/` 폴더에는 소스 파일 외에 아무것도 두지 않는다.** 베타 빌드 시험(`v8-beta-build`)은 `beta/` 안의 모든 파일로 지문을 계산해 커밋된 `dist-beta/build-info.json`과 비교한다. 설명 문서(`AGENTS.md` 등)를 이 폴더에 넣으면 시험이 실패하고, 잠금 스크립트를 다시 돌릴 때도 잠금 목록에 들어간다. 베타 화면 설명은 이 절에만 적는다. 옛 화면 `src/`는 폴더 전체가 아니라 파일 29개의 목록으로 잠겨 있어서 `src/AGENTS.md`는 잠금에 영향이 없다.
- 잠금 지문 계산 방식과 잠금 목록 파일은 바꾸지 않는다.

### 베타 화면(`beta/`)의 역할과 규칙

- 역할: `/beta/`에서 서비스되는 Store 베타의 주 화면(React 19 + Vite, 빌드 결과 `dist-beta/`, 설정 `vite.beta.config.ts`·`tsconfig.beta.json`). 키 입력(`KeysPage`), 자동 수집·데이터(`DataPage`), 결과 보기·자가 검토(`ReviewPage`), 표시 문구 변환(`present.ts`), API 호출(`api.ts`).
- 서버 코드를 가져오지 않는다. 서버가 내보내는 `beta-contract`(타입 파일)만 서버와 함께 쓴다. 옛 화면(`src/`)과 코드를 공유하지 않는다.
- 판단을 다시 계산하지 않는다. 서버가 준 분류·문구를 보여 준다.
- 결과 화면과 내보내기에 항상 "검토 후보 — 법적 판단 아님, 베타"를 표시한다. 자가 검토는 "자가 검토 — 독립 검토 아님"으로 표시한다.
- 서버는 키가 저장되었는지(`configured`)만 돌려준다. 화면은 키 값을 다시 보여 주지 않고, 로그·주소에도 넣지 않는다.
- 앱 제거 시 자료가 지워진다는 고지문과 백업 안내를 화면에서 뺄 수 없다. 고지문 내용은 서버(`/api/beta/notice`)가 정한다.
- 외부 주소로 요청을 보내거나 외부 스크립트·글꼴을 불러오지 않는다(글꼴은 `beta/fonts/`에 포함).
- 시험: 베타 빌드 시험과 베타 E2E(`scripts/e2e-beta-v8.mjs`)를 통과시킨다. 소스를 고치면 `node scripts/build-beta-v8.mjs`로 `dist-beta/`를 다시 만든다. 문구가 바뀌면 Store 스크린샷을 다시 찍는다(`scripts/capture-ui-v8.mjs`).

## 개인 자료와 키

- 커밋·푸시하지 않는 것: `.local/`, `.env*`(예시 파일 제외), DB 파일, 업로드 원본, 민원, 세션, 인증정보, 개인 백업, `backups/`, `private/`. `.gitignore`가 막는 항목이지만 `git add -f`나 다른 경로로 우회하지 않는다.
- 공개 법령 데이터는 `npm run publish:check`를 통과해야 하고, 격리된 공개 수집기가 만든 것만 `data/public/`에 넣는다.
- 저장소, 시험 고정 자료, 문서, 로그, 스크린샷에 실제 키·토큰·이메일·로컬 사용자 경로를 넣지 않는다. 시험은 합성 값만 쓴다.
- GitHub 저장소는 비공개(Private)로 유지한다. 공개로 바꾸지 않는다.
- 로그·오류 메시지에는 본문, 키, 파일 경로를 넣지 않는다. 오류는 `safeMessage`를 거쳐 응답한다.

## Windows

- 하위 프로세스를 띄울 때는 `windowsHide: true`를 준다. 보이는 `cmd.exe`, PowerShell, Windows Terminal 창을 열지 않는다.
- 전역 실행 정책, 사용자 권한, 사용자의 기존 터미널을 바꾸지 않는다.
- 하위 프로세스에는 환경변수 허용 목록을 거친 값만 넘긴다. PowerShell은 신뢰 경로의 파일만 실행한다.

## 전자민원

- 실제 전자민원 자동화를 켜려면 운영자의 사전 허락과 검증된 승인 사이트 설정이 있어야 한다. 시험은 가짜 드라이버와 합성 회신만 쓴다.
- 설치판은 이 기능을 끈다. 이 끔을 풀지 않는다.

## 시험 작성

- 시계는 `koreaDate()`와 고정 시계 선행 로딩(`tests/fixed-now.preload.mjs`, `SHE_TEST_NOW`)을 쓴다. 시험에서 `new Date()`의 실제 현재 시각에 기대지 않는다.
- 데이터 폴더는 임시 폴더를 쓰고 시험 뒤에 지운다. 사용자 `.local`을 읽거나 쓰지 않는다.
- 후보 계층 시험은 `synthetic: true`인 가짜 사용자만 쓴다.
- `work/` 아래 격리 빌드 복사본은 시험 대상이 아니다. 시험은 `tests/**/*.test.ts`만 모은다.

## 의존성과 환경

- Node 24 이상. 의존성 버전은 `package.json`에 정확한 버전으로 고정한다(범위 지정 금지).
- 환경변수는 `.env.example`에 있는 `LAW_OC`, `PORT`, `SHE_EPHEMERAL_AUTH`, `SHE_DATA_DIR`와 설치판 전용 `SHE_INSTALLED`, `SHE_LAUNCH_TOKEN`뿐이다. 새 환경변수를 만들면 자식 프로세스 허용 목록에 필요한지 따져 본다.

## Store 패키지

- 버전은 네 자리이고 마지막 자리는 0이다(Store 규칙). 같은 버전을 다시 올릴 수 없으므로 다시 올릴 때는 버전을 올린다.
- 패키지 스캐너(`scripts/package-scan.mjs`)의 예외 목록(`scan-exceptions.json`)에 항목을 추가할 때는 사용자 승인과 이유 기록이 필요하다.
- 패키지에 넣는 `node.exe`는 해당 Node 버전의 공식 `SHASUMS256.txt`와 일치해야 한다.
- Store 제출은 사용자가 직접 한다.
