# 검토 판단 규칙

이 앱의 결과는 "검토 후보"다. 법적 판단이 아니며, 결과 화면과 내보내기 파일에는 항상 "검토 후보 — 법적 판단 아님, 베타"를 표시한다. 이 문구를 빼는 경로는 만들지 않는다.

## 용어

- **근거(Evidence)**: 법령·조례·행정규칙·해석례·민원 회신·업로드 문서 중 한 건의 원문. 해시, 버전, 공포일·시행일·종료일, 전문·별표·연혁 완전성, 출처 간 불일치 기록을 가진다. 종류는 법령(law), 조례(ordinance), 해석(interpretation), 민원(petition), 문서(document), 공보(gazette).
- **사실(CaseFact)**: 사업장에 관한 입력값 하나(키, 값, 출처, 확정 여부). `confirmed`는 "입력이 끝났다"는 뜻이지 서류로 증명되었다는 뜻이 아니다. 증명 정도는 별도의 출처 정보(provenance)가 나타낸다.
- **기준일**: 어느 날짜의 법령으로 볼지를 정하는 날짜. 오늘 날짜가 아니다. 모든 날짜는 한국 달력(`koreaDate`)으로 계산한다.
- **규칙(Rule)**: 사람이 승인한 하나의 비교 조건(사실 하나를 값과 `eq/gte/gt/lt/lte`로 비교).

## 쟁점 3분류

| 분류 | 의미 | 낼 수 있는 경우 |
|---|---|---|
| `clear_risk` | 명백한 위험 | 사람이 승인한 결정론적 규칙만, 아래 모든 조건이 충족될 때 |
| `human_review` | 사람이 검토 | 인용이 검증된 쟁점 중 확정할 수 없는 것 |
| `more_data` | 자료 부족 | 검증 가능한 인용이 없거나, 인용이 깨졌거나, 참고자료만 인용한 쟁점 |

**현재 상태**: 승인된 규칙의 입력 조건이 모두 일치해도 결과는 `human_review`로만 나온다. 조건이 "임계값 충족"일 뿐 의무 불이행을 입증하는 것이 아니고, 적용 범위·이행 기한·예외 검증 단계가 아직 없기 때문에 일부러 막아 두었다. 규칙 평가는 빈틈이 없고 필수 질문이 모두 답해진 검토에서만 돈다. 그래서 기본 앱에서 `clear_risk`는 사실상 나오지 않는다. 이 막음을 풀거나 `clear_risk` 경로를 새로 여는 일은 사용자 결정이 필요하다.

### AI 출력의 처리

- 모델이 `clear_risk`를 내면 `human_review`로 내리고 결론을 "모델이 제안한 쟁점입니다… 확정할 수 없습니다"로 바꾼다. 모델은 `clear_risk`를 만들 수 없다.
- 인용(근거 ID + 발췌문)이 하나라도 원문과 맞지 않으면 그 인용을 빼고 "인용 원문이 일치하지 않아 제외" 사유를 남기며, **쟁점 전체를 `more_data`로 내리고** 결론을 "원문으로 검증할 수 없어 보류"로 바꾼다. 유효한 인용이 0개일 때도 같다.
- 유효 인용이 전부 해석례·민원 회신·업로드 문서뿐이면 `more_data`로 내린다. 개별 회신만으로 현재 사업장의 의무를 확정할 수 없기 때문이다. 이때 "현재 기준일의 법령·조례 원문과 사업장 사실 대조"를 부족 항목에 넣는다.
- 인용 검증: 공백을 정규화한 뒤 8자 이상의 발췌문이 근거 원문 안에 **그대로 이어져 있어야** 한다. 요약·말바꿈·떨어진 문장 조합은 거절한다.
- 빈틈이 하나라도 있으면 쟁점에 "미확인 범위가 있어 확정적인 준법 판단으로 사용할 수 없습니다"를 붙인다.

## 근거 빈틈 (하나라도 있으면 확정 불가)

- 국가 법령 전문이 없다.
- 해당 시·도 조례 전문이 없다.
- 같은 법규에 시행일·공포일이 같은 서로 다른 원문이 있다(`sourceId`가 겹침).
- 법령·조례 근거의 출처 간 정보가 불일치한다.
- 전문 또는 연결 조문이 불완전하다 / 별표·서식 확인이 안 됐다 / 예외·위임·경과조치 검증이 안 됐다.
- 기준일이 오늘보다 과거인데 연혁 완전성이 확인되지 않았다.
- 기준일 시점에 시행 중이 아니거나(시행일 이전, 종료일 이후, 폐지), 적용 지역(전국 또는 해당 시·도)이 아니다.
- 원문 확인(`fetchedAt`)이 24시간보다 오래됐거나 미래 시각이다(1분 이상 앞서면 거절).

완전한 근거(`coverage.complete`)는 이 빈틈이 0개일 때만 성립한다.

## 사실

- "모름, 확인 중, 미확인, 아직, 미제출, 미정, 예정, 추정, 서류가 없음, 조회 0건, 조회 실패, 응답 시간 초과, unknown" 같은 답은 **확정으로 치지 않는다**. 규칙의 필수 사실이 이런 값이면 규칙은 작동하지 않는다.
- 같은 키의 사실이 둘 이상이면 규칙은 작동하지 않는다. 출처 충돌이 기록된 사실도 마찬가지다.
- 사실의 출처 구분: 사용자 / 모델 / 파생. 확인 수준: 미확인 / 서류 검토 / 현장 확인. 모델이 만든 사실은 사용자가 확정하기 전까지 확정이 아니다.
- 수치 조건은 `compareDecimal`로 비교한다. 비교할 수 없는 값(숫자가 아님)은 일치로 치지 않는다.
- 예외 사실(`exceptionFacts`)은 값이 정확히 "해당 없음"일 때만 예외가 없다고 본다. 다른 값이면 규칙은 아무것도 내지 않는다.
- 서류가 없다는 사실은 무허가를 뜻하지 않는다. 허가서 미제출을 위반의 증거로 쓰지 않는다.
- 모델의 결론, 출처 날짜 불일치, 어휘가 비슷한 인용은 위반의 증거가 아니다.

## 규칙 승인

- 규칙은 검토자 확인서를 등록해야만 켜진다. 처음에는 승인된 규칙이 0개이고, 시험용 가상 규칙을 운영에 복사하지 않는다.
- 확인서가 갖춰야 할 것: 검토자 이름(2자 이상), 지역·시군구·기준일, 설명(30자 이상), 지자체 공보 주소(https, `.go.kr` 도메인), 위임·예외·별표·연혁을 확인했다는 네 가지 표시, 현재 적용 근거 **전체**의 해시(2개 이상).
- 해시 목록이 현재 적용 근거 전체와 하나라도 다르면 거절한다. 일부만 승인할 수 없다.
- 국가법과 해당 시·도 조례가 모두 있어야 한다. 출처 간 불일치가 남아 있으면 거절한다.
- 규칙의 인용은 각 근거 원문에서 그대로 검증되어야 하고, 조건에 쓰인 사실은 필수 사실 목록에도 있어야 한다.
- 승인은 24시간만 효력이 있다. 같은 지역·시군구·기준일이라도 원문이 바뀌거나 24시간이 지나면 다시 받는다.
- 승인과 규칙 저장은 한 묶음(SAVEPOINT)이다. 중간에 실패하면 모두 되돌린다.
- 자동 수집만으로는 승인하지 않는다. 원문 확인과 사람의 검토는 별개다.

## 자가 검토

- 혼자 쓰는 설치를 위한 기능이다. 완료된 검토에만 할 수 있고, 메모 15자 이상과 사실·근거·한계 세 가지 확인이 필요하다.
- 항상 "자가 검토 — 독립 검토 아님"으로 표시하고, 마크다운·CSV 내보내기에도 같은 표시를 붙인다. 독립 검토(작성자와 검토자가 다른 경로)로 세지 않으며, 독립 검토 경로는 바꾸지 않는다.
- CSV에 쓰는 문구가 `= + @ - 탭 CR`로 시작하면 앞에 작은따옴표를 붙여 수식으로 해석되지 않게 한다.

## 수량 합산

- 품목마다 입력 단위와 그 품목의 지정수량 단위가 같은 종류(질량 g·kg·t, 또는 부피 mL·L·kL)여야 한다. 품목의 배수(수량 ÷ 지정수량, 단위 없는 비율)를 모두 더한다. 질량과 부피를 서로 환산하지 않으며, 한 품목 안에서 종류가 다르면 거절한다.
- 합산 대상 저장·취급 단위를 먼저 확인해야 계산한다. 수량이 음수이거나 지정수량이 0 이하이거나 숫자가 아니면 거절한다.
- 기본 제공 계산기의 지정수량이 법적 지정수량으로 승인되는 것은 아니다.

## 사업장 자료와 개인정보

- AI로 보내는 문서 본문·문서 이름·질문·답변·사실값과 접수(intake) 질문 문구에서는 주민등록번호 형식, 이메일, 전화번호를 `[주민번호 삭제]` 등으로 바꿔서 보낸다. 저장된 원문은 바꾸지 않는다. 이 가리기는 형식 일치 방식이라 이름·주소·사업자번호는 가려지지 않는다.
- 업로드 문서에서 읽어낸 사실도 사용자가 확인하기 전에는 확정이 아니다.

## 보존·삭제

- 기본은 계속 보관한다. 30·90·365일 자동 삭제를 고를 수 있고(업로드 원본이 대상), 언제든 영구 삭제할 수 있다.
- 원본이 지워진 검토에는 "원본 삭제됨 — 재검토 불가"를 표시한다.
- 삭제 기록에는 종류·참조 ID·시각·사유만 남기고 본문과 파일 이름은 남기지 않는다.

## 공개 법령 자료

- 번들은 공개 수집기가 만든 공식 자료만 담는다. 번들에서 가져온 근거는 `verified=false`와 검증 메모 "공개 데이터 수입: 현장 검증 별도"로 시작하고, 검토자 확인서로 승인되기 전에는 그대로다.
- 같은 근거(출처 ID, 종류, 제목, 지역, 조문, 내용 해시, 버전, 시행·종료일, 폐지 여부가 모두 같은 것)를 다시 저장할 때는 이미 붙은 검증·별표 완전성·연혁 완전성 표시를 유지한다. 내용이 바뀐 새 버전은 검증 표시 없이 새 근거로 저장된다.
- 번들의 갱신은 자동이 아니다. 새 앱 버전을 만들기 전에 사람이 수집하고 점검한다.

## 후보 계층

- 안전관리자 미리보기를 켜면 결과에 "[검토 후보 — 법적 판단 아님, 베타]"를 붙이고, 법적 기준일을 2026-10-08로 두며, 메모리 DB에서 평가한다. 이 경로는 `clear_risk`를 내지 않는다.
- 후보 계층의 컴플라이언스 평가기는 승인 상태의 항목에 `clear_risk`를 낼 수 있다. 그래서 후보 계층을 기본 경로에 연결하면 위 "현재 상태"의 막음이 풀리는 셈이 되므로, 연결은 사용자 결정 사항이다.
- 안전관리자 의무 6가지는 후보 계층에서만 평가한다. 기본 경로의 검토 결과에는 섞지 않는다.
- 후보 계층을 기본 경로로 연결하려면 풀어야 할 조건이 남아 있다(기본 표의 암호화·소유권 구분, 보호 사례 결과가 평문 표로 복사되는 문제, 내보내기 점검의 빈틈, 화면 변경이 필요한 수동 보완·독립 검토 화면, 전문가 검토와 활성화). 연결 여부는 사용자 결정이다.
