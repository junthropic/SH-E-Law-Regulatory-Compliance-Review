# 시험 결과와 운영 검증표

구현 환경: Windows, Node.js 26.7.0. 기준일 2026-10-03. 상세 수정·외부 연결 상태는 [재검토 기록](recheck-2026-10-03.md)을 확인하세요.

## 실행한 시험

- TypeScript 검사, 서버 JS 생성, Vite 생산 빌드: 통과
- 자동시험: 일반 Windows 사용자 프로필에서 **90개 전부 통과**. GitHub의 Windows·Linux CI 결과는 재검토 기록 참고
- Korean Law MCP 4.15.5: 실제 stdio handshake·도구 목록 조회 통과. 앱의 법제처 OC 직접 연동은 18개 출처·225개 원문 첫 수집 성공
- API 시험: Host·Origin·CSRF 차단, 검토 저장·분류·내보내기, 입력 오류, 민원 미승인 차단
- 법률 판단 통제: 허위 인용 보류, LLM 확정 금지, 검토 규칙 승인·지역·시행일·예외·허가정보·별표·해시·최신성 조건
- 스트림: 한글과 CRLF 분할, 완료 이벤트 누락, 출력 뒤 실패/미완료, 한도 오류
- OAuth 모의 발급자: PKCE·state·실제 RSA 서명·nonce·audience·scope·토큰 교체·동시 갱신·취소
- 자료: TXT 중복 제거, 한국어 DOCX 추출, 백업 무결성·복원, 공개 번들에 개인 민원 혼입 거부
- 독립 헤드리스 Chrome: 검토 실행 → 결과 → TXT 업로드 → 메타데이터 저장 → 원본 대조 표시 → 18개 출처 → 연결 설정 → 모바일 화면. 페이지 오류 없음
- 공개 데이터 검사: 통과. 초기 번들 **실제 법규 0개**; 데이터가 있다고 가장하지 않음

DPAPI 실기기 시험은 일반 Windows 사용자 프로필과 Windows CI에서 통과했습니다. 암호화된 파일을 새 Vault 인스턴스에서 다시 읽고 삭제하는 흐름을 확인했습니다. 제한된 도구 프로필의 실패는 앱 자체의 DPAPI 실패와 구분합니다. 로컬 앱은 임시 메모리 모드에서 일반 Windows 사용자의 보호 저장 모드로 전환했습니다. 실제 ChatGPT 로그인·모델 조회·가상 사례 응답·원격 로그아웃은 성공했고, 보호 저장 이후 재시작 유지 검증을 진행합니다.

HWP/HWPX/PDF 추출은 kordoc 어댑터를 구현했으나 실제 업무 서식별 품질을 아직 검증하지 않았습니다. OCR, 복잡한 표, 도면의 자동 이해는 제공하지 않습니다.

## 첫 운영 검증 절차

1. 사용자의 ChatGPT 계정 연결, 모델 조회, 작은 실제 질의 한 건, 토큰 만료/재연결을 확인합니다.
2. 법제처 OC로 국가법과 경기도·울산·인천을 수집합니다. API의 승인 범위와 전문·부칙·별표 누락 여부를 확인합니다.
3. 저장량 경계값, 혼합물, 예외 적용, 기존 허가 변경, 설치·시행 시점이 다른 사례를 전문가가 원문과 대조합니다.
4. 상위법 개정·조례 공포·조례 시행일이 엇갈리는 사례에서 '수집 지연'과 '실질 미정비 검토'가 혼동되지 않는지 확인합니다.
5. 관련 시군구 및 공보의 공식 주소와 기관별 자동수집 경로를 확정합니다. 아직은 확인서로 사람이 검토한 범위만 기록합니다.
6. 검토한 원문 해시와 규칙만 승인합니다. 다른 시·도·날짜에는 해당 승인을 재사용하지 않습니다.
7. 국민신문고는 승낙 이후 허용 범위에서 별도 실연동 시험을 진행합니다.

이 검증이 완료되기 전까지는 운영상 최종 판단을 대체하는 서비스로 표시하지 않습니다.
