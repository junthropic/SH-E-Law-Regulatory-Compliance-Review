# 시스템 구성

SH·E는 사용자 PC 한 대 안에서만 도는 앱이다. 서버, 저장소, 화면이 모두 같은 Windows 사용자의 PC에 있고, 제작자 서버는 없다. 사용자는 브라우저로 `http://127.0.0.1:4317`에 접속하고, Store 설치판은 C# 런처가 서버를 띄운 뒤 브라우저를 연다.

## 구성 요소와 연결

```
브라우저
 ├─ /        옛 화면 (src/ → dist/)
 └─ /beta/   베타 화면 (beta/ → dist-beta/)
      │  HTTP + 쿠키 세션 + CSRF 헤더 (127.0.0.1만)
      ▼
Fastify 서버 (server/)
 ├─ 접근 검문: 루프백 → Host → Origin → 경로 판정 → 교차 사이트 → 세션 → CSRF (새 세션을 줄 때는 실행 토큰)
 ├─ 검토 파이프라인 (reviews.ts → legal.ts, verification.ts, fact-checks.ts)
 ├─ 저장소 (store.ts): node:sqlite (WAL, FTS5 trigram) + 업로드 원본 파일
 │     └─ 저장 암호화 (storage-crypto): 표 reviews·documents·settings와 원본 파일을 밀봉
 ├─ 보호 저장소 (vault.ts): 인증키·로그인 토큰, Windows 사용자 보호(DPAPI)
 ├─ 외부 통신 가드 (egress-guard): 허용 목록 밖 호스트는 연결 전에 거부
 └─ 수집기 (sources.ts, public-apis.ts, bundles.ts): 법령·공공 API → 근거(Evidence)
      │
      ▼ 허용 목록만
 법제처 Open API(law.go.kr) · 공공데이터포털 · 도로명주소 · 지자체 공보 · 사용자가 켠 AI(OpenAI 로그인)
```

- 공용 타입·문구·날짜 규칙은 `shared/`에 있고 서버와 두 화면이 함께 쓴다. `shared/`는 서버 전용 모듈을 가져오지 않는다.
- 공개 법령 번들 `data/public/bundle.json.gz`는 앱에 같이 들어간다. 서버가 시작될 때 한 번 가져온다. 이 번들은 격리 DB를 쓰는 공개 수집기(`npm run sync`)가 만들고 `publish:check`를 통과해야 한다.
- 후보 계층(2~7단계에 만든 컴플라이언스·LegacyBridge·안전관리자 의무·교육 등)은 `server/`에 있지만 기본 앱 경로에 연결되어 있지 않다. 시험용 가짜 사용자(synthetic principal)를 넘겨야만 `createApp`이 연결한다. 기본 경로에서 쓰이는 유일한 접점은 설정 스위치 `preview.safetyManagerV7`(기본 꺼짐)이다.
- 설치판(`SHE_INSTALLED=1`)은 MCP, 공개 법령 자동 업데이트, 전자민원 자동화, 평문 JSON 백업을 끈다. 개발 실행에서는 켜져 있다.

## 시작 순서 (server/index.ts)

1. 실행 토큰을 환경변수에서 읽고 지운다 → 설치판인데 토큰이 없으면 서버를 열지 않고 종료한다.
2. 처리되지 않은 예외 핸들러를 건다.
3. 외부 통신 가드를 설치한다 (이후 모든 `fetch`/`http(s)`가 허용 목록을 거친다).
4. 저장 암호 키를 연다(없으면 만든다).
5. `Store`와 앱을 만든다.
6. AI 전송 승인 관문을 건다.
7. 기존 평문 자료를 암호화 저장으로 이전한다.
8. 보존 기간이 지난 원본을 지운다(이후 하루 한 번 반복).
9. 공개 법령 번들을 가져온다.
10. `running` 상태로 남은 검토를 실패로 바꾼다(서버가 중간에 꺼진 경우).
11. 127.0.0.1에서 수신을 시작한다. 개발 실행에서만 4327의 옛 주소를 4317로 돌려보내는 리다이렉트를 같이 연다.

순서를 바꾸면 안 된다. 외부 통신 가드(3)보다 먼저 네트워크 코드가 돌면 허용 목록이 우회되고, 암호 키(4)보다 먼저 저장소를 열면 평문으로 쓰기 시작한다.

## 대표 흐름: 검토 한 건

1. 화면이 `/api/bootstrap`으로 세션 쿠키와 CSRF 값을 받는다. 설치판은 런처가 준 실행 토큰 헤더가 맞을 때만 세션을 준다.
2. `POST /api/reviews`가 요청(질문 10자 이상, 17개 시·도 중 하나, 기준일 `YYYY-MM-DD`)을 검증하고 `running` 상태의 검토를 만든 뒤 바로 돌려준다. 같은 시각에 진행 중인 갱신·검토가 있으면 변경 요청은 409로 거절한다.
3. 백그라운드에서 `runReview`가 돈다. 근거(Evidence)를 검색하고, 마지막 원문 확인이 24시간 안인지 본다(국가법·지역 조례 둘 다). 빈틈 목록(gaps)을 만든다.
4. 사실(CaseFact)을 모으고, 기본 질문 5가지(물질, 수량, 시설, 허가, 날짜)를 미확인 항목으로 둔다.
5. 승인된 규칙을 평가하고, AI를 켰다면 AI 분석을 받아 `enforceIssue`로 인용 검증과 분류 하향을 거친다.
6. 쟁점이 3분류로 정리되어 저장(밀봉)되고, 화면은 `/api/reviews/:id/events`로 진행 상황을 받는다.

## 경계

- 경계를 넘는 것: 허용 목록 호스트로의 법령·공공 API 요청, 사용자가 건별로 승인한 AI 전송 내용(OpenAI 로그인 경유).
- 넘지 못하는 것: 제작자 서버로의 모든 전송, 허용 목록 밖 호스트, 127.0.0.1 밖에서 들어오는 접속, 승인되지 않은 AI 전송.
- 모듈 의존 방향: 화면 → (HTTP) → 서버 → `shared/`. 서버는 화면 코드를 가져오지 않고, `shared/`는 서버·화면 어느 쪽도 가져오지 않는다.
