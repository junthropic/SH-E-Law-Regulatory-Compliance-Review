# EHS 추가 API 활용신청 체크리스트

확인일: 2026-10-07. 적용 범위: 제조업·위험 작업환경의 자연어 법령/조례 검토, 해석사례 검색, 현장 자료 대조.

앱 반영: 연결 설정에 A 12개와 B 14개 전체의 신청 링크·사용 목적·키 저장/삭제 항목을 추가했다. 2026-10-08 기준 추가 26개 모두 연결 체크·실제 검색·자료 저장까지 연결했다. 상세 사용법은 [추가 API 조회](additional-api-search.md)를 참고한다.

이 문서는 공식 서비스 소개와 제공 범위를 확인해 선정한 개발 제안이다. 아래 목록은 신청 안내이며, 각 계정의 현재 승인 상태는 앱에서 연결 체크로 확인한다. 이미 연결한 6개 서비스는 재신청 대상에서 제외한다. 이용기간 갱신은 사용자가 Aside로 관리하며 이번 개발 범위에 포함하지 않는다.

## 1. 신청 범위 결정

- 자연어 조회는 기존 6개에 GHS·결정례·재해사례를 더해 관련 조건이 있는 서비스만 계획한다. 나머지 서비스는 공공자료 조회에서 식별 조건을 직접 입력한다.
- 전체 EHS 검토를 보강하려면 기존 법제처 OC의 서비스 이용 범위를 먼저 확인한다.
- 추가 A 목록 12건은 해석사례·위험요인·위탁업체·주소 및 입지 조회를 위한 추천 목록이다. 모두 현재 첫 기능의 필수 의존성인 것은 아니다.
- B 목록 14건은 설비 인증서 및 사업장 인허가 자료를 대조하는 기능까지 준비할 때 함께 활용신청할 후보이다.
- 법령 검토 정확도에는 API 개수보다 기준일, 별표·부칙, 위임관계, 실제 사업장 자료의 일치가 중요하다. 이 목록을 전체 법령·조례의 완전한 수집 보장으로 취급하지 않는다.

## 2. 기존 법제처 OC: 이용 범위 확인·확대

사이트: [국가법령정보 공동활용 API 목록](https://open.law.go.kr/LSO/openApi/guideList.do)

기존 계정으로 아래 서비스군의 신청·승인 상태를 확인한다. 각 항목마다 별도 신규 키를 발급받는 방식으로 진행하지 않는다. 기존 OC로 가능한 범위와 추가 서비스 신청 필요 여부를 확인한다. 법령 체계도 등 부가서비스는 법령서비스 신청 시 별도 신청 없이 이용 가능하다고 안내되어 있다.

| 확인할 서비스군 | 구현 목적 |
|---|---|
| 현행·연혁 법령, 조항호목, 변경이력, 신구법 | 질문 기준일에 해당하는 조문 선택 및 개정 추적 |
| 자치법규 본문, 법령↔자치법규 연계, 위임법령 | 시·도 및 시·군·구의 위임조례 탐색 |
| 법령·행정규칙·자치법규 별표·서식 | 수량표·시설기준·서식 및 예외의 원문 확보 |

| 법제처 해석례, 판례, 행정심판례 | 해석 쟁점과 적용 조건 대조 |
| 부처별 1차 해석 | 고용노동부·소방청·환경 담당 부처 등 소관기관의 해석 확보 |

부칙은 본문과 별도로 존재하는 누락 가능 구간으로 추적한다. 위임·연계 API에서 검색되지 않았다고 적용 조례가 없다고 판단하지 않는다. 별표 API 역시 원본 파일 파싱 및 적용 버전 검증까지 완료되어야 검증 근거로 사용한다.

공보와 부칙·별표의 누락 문제는 추가 API 키만으로 해결되지 않는다. 첨부파일 다운로드, PDF/HWP/HWPX 추출, 표 구조 보존, 원문 위치와 해시, 개정본 연결이 필요하다.

## 6. 이번 신청 목록에서 제외한 자료와 이유

- 보건관리자 선임현황 등 통계·현황 파일: 선임 의무의 법적 기준 자체가 아니다. 법적 의무 판정은 법령, 업종, 근로자 수, 현장 조건을 통해 수행한다.
- [특정소방대상물정보서비스](https://www.data.go.kr/data/15155780/openapi.do) 및 [소방시설정보서비스](https://www.data.go.kr/data/15155779/openapi.do): 현재 공식 설명의 대상이 숙박시설이며 후자는 스프링클러 자료다. 제조업 전체의 소방시설 확인 수단으로 추천하지 않는다.
- [사업장폐기물 인계정보](https://www.data.go.kr/data/15124992/openapi.do): 설명상 년월·폐기물·관할청별 위탁량·운반량·처리량 등이다. 자사 올바로 전자인계서 조회·작성 연동으로 간주하지 않는다.
- 실외 대기질, 기상, 전국 사고 통계: 향후 알림·통계 기능에서 검토할 수 있으나 현재 법령·조례 검토의 필수 신청 대상에서 제외한다.
- 일반 웹 검색, 지도 표시, OCR, 임베딩 등 상용 API: 현재 설계에서 새로운 유료 키를 필수 요구하지 않는다. 원문 추출 품질이나 검색 성능 평가에 따라 도입 여부를 결정한다.
- 기존 카탈로그에 있으나 이번에 공식 페이지를 확인하지 못한 업무상 질병사례 API 등: 즉시 신청 확정 목록에 넣지 않았다. 원본 카탈로그 명칭만으로 서비스의 현행 제공 여부를 보장하지 않는다.

## 7. 실제 신청 및 등록 절차

1. A01~A11 및 선택한 B 항목을 공공데이터포털 기존 계정으로 각각 활용신청한다.
2. 활용목적에는 실제 계획을 기재한다. 예: "제조업 환경·안전·보건 담당자의 자연어 질의에 대해 법령·조례와 공공 참고자료를 검색하고, 현장 자료와 대조하여 출처와 추가 확인사항을 제공하는 내부 업무지원 서비스 개발."
3. API별 활용가이드·명세를 보관하고, 서비스명/데이터 ID/개발 승인/운영 승인/호출한도/샘플 조회조건을 기록한다. 키 문자열이 같아도 서비스별 활용신청 상태는 별도로 확인한다. 공식 포털의 [권한 오류 안내](https://www.data.go.kr/data/15149423/openapi.do)는 해당 API의 활용신청과 접근 권한을 확인하도록 안내한다.
4. A12는 주소기반산업지원서비스에서 도로명주소 검색 API 승인키를 신청한다. 공공데이터포털 서비스키와 구분한다.
5. 법제처 기존 계정에서 2절의 서비스 이용 범위를 확인한다. 승인되지 않은 서비스군은 추가 신청한다.
6. 로컬 앱의 연결 설정에서 해당 서비스 항목에 등록한다. 기존 6개 입력칸에 다른 서비스 키를 덮어쓰지 않는다. 채팅·Git 저장소에는 키를 기록하지 않는다.
7. 연결 확인은 저장 성공과 분리한다. 최소 1개 실제 검색→상세/첨부→정규화→출처 표시까지 확인한 서비스만 '연결 검증 완료'로 표시한다.

## 8. 모듈 연결과 결과 판정

| 자료군 | 연계 기준 | 결과에서의 역할 |
|---|---|---|
| 법령·조례·행정규칙·별표 | 법령 ID, 조문, 관할, 시행일, 원문 버전 | 법적 기준 후보 및 검증 근거 |
| 해석례·결정례·민원 Q&A | 문서번호, 회신일, 적용 조문, 사실관계 | 해석 쟁점·추가 확인 근거 |
| 화학물질 정보 | CAS 정확 일치, 성상, 농도, 혼합물 여부 | 물질 사실 대조 및 필요한 질문 |
| 재해사례·기술지침 | 업종, 작업, 설비, 위험요인 | 위험요인 탐색·예방 참고 |
| 인허가·처분 현황 | 사업장/업체 식별자, 주소, 처분 기간 | 제출자료와 대조·불일치 알림 |
| 인증·승인 정보 | 인증번호, 모델, 사양, 승인/취소일 | 인증서 및 제품 정보 대조 |

추가 API 조회 결과도 기존 검증 관문을 통과해야 한다. 날짜 불일치, 후보 다중 일치, 누락, 호출 실패는 '추가 확인 필요'로 남기고, 사례나 현황 조회만으로 확정 위반을 만들지 않는다. 명확한 리스크 출력은 검증된 근거·확인된 현장 사실·승인된 결정 규칙이 모두 갖추어진 항목으로 제한한다.

권장 구현 순서: 법제처 이용 범위·연계 보강 → 주소/관할 정규화 → 해석례·GHS·사례 연결 → 폐기물/대행업체 대조 → 설비 인증·사업장 인허가 대조. 실제 '경기도 화성시 / 소량위험물 저장·취급' 검증은 법령과 경기도·화성시 원문, 수량·품명·성상·저장방식 및 관련 허가자료의 대조를 먼저 완료한다.
