## 2. 실행 경로

`server/index.ts`(설치 앱 진입점) 순서: 예외 출력 정리 → 외부 전송 허용 목록 설치 → (Windows) DPAPI 데이터 키 열기 → 암호화 Store로 앱 생성 → 평문 이관 → 자동 삭제 확인. Windows가 아닌 환경은 개발용으로 보고 암호화 없이 경고만 출력한다.

## 3. 범위 밖·남은 일 (사실대로)

- **AI 미리보기 화면 연결**: 동의·미리보기·승인·기록 장치와 차단은 완료. 실제 검토 화면에서 미리보기를 띄우는 연결은 화면 단계(단계 3)에서 한다. 지금 기본 앱은 원래부터 AI 전송 경로가 닫혀 있다(`EgressDenied`).
- **보호 사례 결과 표시**: B-2로 평문에는 참조만 남으므로, 결과를 보여 주는 화면·export 연결은 스위치 단계(단계 2)에서 보호 저장소를 거쳐 붙인다.
- **백업 내보내기 파일**: `/api/backup`은 아직 평문 JSON 다운로드다. 암호화 백업 내보내기·가져오기는 단계 3·4 범위(지시서 단계 4 "백업은 암호화 상태로 내보낸다").
- **평문으로 두는 것**: 공개 법령 본문(`evidence`, 검색 색인 `evidence_fts`, `legal-raw/`, `legal-attachments/`), `sources`, `rules`, 일반 감사 기록(id·고정 문구만). 회사 자료가 아니어서 검색 가능하게 둔다.
- **격리 경로 표**: v2~v7 격리 표(`v2_*`, `v3_*` 등)는 기본 앱 경로에서 만들지 않는다. 보호 사례 본문은 이미 AES-GCM(`v4_payloads`).
- **외부 전송 감시 밖**: `korean-law-mcp` 자식 프로세스(법제처 조회, stdio)와 민원 수집용 Edge(이미 `www.epeople.go.kr`만 허용하는 별도 경로 제한)는 Node 감싸기 밖이다. 둘 다 법령·공공 출처만 접속한다.
- **동작 변경**: 기존 "공개 자료 묶음 갱신"(`/api/public/update`)은 제작자 GitHub 저장소에서 받으므로 설치 앱에서는 차단된다(지시서 §4-1: GitHub Actions 수집 결과를 사용자 앱으로 보내지 않음). 문서 삭제는 이제 삭제 기록을 남기고 관련 검토에 "원본 삭제됨" 표시를 붙인다.

## 4. B-4(회사별 데이터 분리) 제외 근거

설치형 베타는 한 PC의 한 Windows 사용자가 자기 회사 자료만 다루는 단일 사용자 앱이다. 서버는 127.0.0.1에만 열리고(V8-N01·N02), 자료는 그 Windows 사용자 키로만 열린다(V8-E04·E05). 같은 앱 안에 여러 회사 자료가 섞이는 구조가 아니므로 회사(tenant)별 분리는 이번 범위에서 제외한다. 여러 회사가 한 서버를 함께 쓰는 형태로 바뀌면 B-4를 다시 연다.
