# v8 단계 2 — 미리보기 스위치와 v7 연결

작성 2026-10-13. 기준 main `b8f3964`. 시험은 합성 자료와 막힌 네트워크만 쓴다.

## 1. 스위치

- 설정 `preview.safetyManagerV7`, 기본 `false`. `GET /api/preview`로 상태를 보고, `POST /api/preview {safetyManagerV7}`로 켜고 끈다. 바꿀 때마다 감사 기록 `preview_switch`을 남긴다(V8-P05).
- **꺼짐**: 기본 앱 검토의 마무리 단계가 아무것도 하지 않는다. 결과·export는 이전과 같다.
- **켜짐**: 기본 앱 검토에 v7 연결(`LegacyBridge("v7")`)이 붙는다. 질문을 의무별 후보로 나누고, 산업안전보건법 안전관리자 질문은 산업안전보건법 후보로 보낸다. 위험물안전관리법 안전관리자 후보는 섞지 않는다.

## 3. 저장 암호화와의 관계

v7 연결은 원래 평가 결과를 `v2_entities`·`v3_shadow` 같은 평문 표와 `v2-originals/` 파일에 쓴다. 이대로 붙이면 단계 1의 저장 암호화가 깨진다. 그래서 다음처럼 처리한다.

- 켜짐 상태의 평가는 **메모리 안 임시 DB**에서 하고, 끝나면 버린다.
- 업로드 원본은 임시 평가로 복사하지 않는다(문서 id를 비운 사본으로 평가).
- 실제 저장되는 것은 라벨이 붙은 결과(검토 기록, 암호화)뿐이다.
- 시험 V8-P04에서 암호화를 켠 자료 폴더에 질문 평문이 없고, 임시 폴더도 남지 않는 것을 확인했다.

한계: 후보 평가에는 업로드 문서가 연결되지 않는다. 후보는 "사실·근거 확인 필요"(보류) 상태로 나오며, 문서 사실을 연결한 판정은 단계 3의 사실 보완·검토 화면에서 보호 저장소를 거쳐 다룬다.

- B-3 검사(`server/export-check-v8.ts`)는 이제 보호 사례 **참조 문구**로 보호 참조 혼입을 찾는다. 미리보기 후보도 같은 의무 id(`safety_manager.*`)를 쓰므로, id로 찾으면 정상 후보 export까지 막혔다. V8-B3 시험은 실제 참조(`protectedReference`)를 넣도록 고쳤다. 확인하는 내용은 같다.
- `Store`에 메모리 DB 선택지(`memory: true`)를 추가했다.
