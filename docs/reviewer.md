# 검토자 확인서와 규칙 승인

초기에는 승인된 법률 규칙이 **0개**입니다. 시험의 가상 규칙을 운영용으로 복사하지 마세요. 법적 지식, 정확한 적용법과 예외를 검토한 사람이 아래 형식의 확인서를 작성합니다.

확인서는 현재 검색된 원문 **전체의 해시**, 검토자, 지역·시군구·기준일, 공보 URL, 별표·연혁·예외·위임 검토 기록을 포함합니다. 같은 날짜·지역이라도 원문이 바뀌거나 24시간이 지나면 다시 확인해야 합니다. 원문 확인과 사람의 검토는 별개이며, 자동 수집만으로 승인하지 않습니다.

```json
{
  "reviewer": "실제 검토자 이름",
  "region": "경기도",
  "municipality": "화성시",
  "asOf": "2026-10-02",
  "note": "공보와 법령센터의 버전, 관련 시군구 위임 규정, 별표 및 경과조치를 대조한 실제 검토 내용",
  "gazetteUrl": "https://www.gg.go.kr/실제로대조한공보주소",
  "delegationChecked": true,
  "exceptionsChecked": true,
  "annexesChecked": true,
  "historyChecked": true,
  "evidenceHashes": ["현재 적용 근거 각각의 실제 SHA-256"],
  "rules": []
}
```

앱의 **검토자 확인서 등록** 또는 `npm run approve -- 확인서.json`을 사용합니다. 위 예시는 구조 설명이며 그대로 승인할 수 없습니다. 근거 목록이 현재 검색된 전체와 다르면 거절합니다. 확인서는 로컬 설정과 감사 기록에 저장되며 공개 번들·일반 백업에 넣지 않습니다.

규칙은 `shared/types.ts`의 `Rule`과 `server/schemas.ts`의 `RuleSchema`를 따릅니다. 필수 사실은 모두 사용자가 답해야 하며, 예외는 실제 미적용이 확인된 경우에만 `해당 없음`으로 입력합니다. 수치 조건에 사용되는 사실의 단위·계산 범위도 별도의 필수 사실로 설계해야 합니다. 기본 제공 배수 계산기의 값이 자동으로 법적 지정수량으로 승인되지는 않습니다.

`quotes`는 근거 해시를 키로, 원문의 정확한 발췌를 값으로 사용합니다. 현재 규칙 엔진은 단일 비교 조건(`eq`, `gte`, `gt`, `lt`, `lte`)을 지원합니다. 복잡한 예외 조합이나 법적 해석을 이 연산자에 무리하게 끼워 맞추지 말고 사람 검토로 남깁니다.
