## 실행 증거

- `npm run check`: 일반 Windows 사용자 프로필에서 TypeScript·생산 빌드 및 **90개 시험 전부 통과**. 제한된 도구 프로필에서는 DPAPI 시험을 건너뛰므로 사용자 프로필에서 별도 확인했다.
- [GitHub CI](https://github.com/junthropic/SH-E-Law-Check/actions/runs/37099078587): `2042f6c8f46ed20f3c6a27de8a70c8092cc0aa27`의 Windows·Linux 빌드·시험·공개 데이터 검사 통과. Linux의 Windows 전용 DPAPI 시험은 적용 대상 아님.
- `npm run test:e2e`: 별도 시험 DB와 독립 headless Chrome. 검토·기록 수·문서 업로드·메타데이터·원본 확인·18개 출처·설정·모바일·페이지 오류 검사 통과.
- Codex 앱 브라우저에서도 결과 분류와 설정 화면 확인. 미확인 허가를 위반으로 확정하지 않음.
- `npm run publish:check`: 통과. 로컬 첫 수집에서 위험물 관련 18개 출처·39개 법규의 225개 현행/연혁 버전 수집 성공. GitHub 공개 번들은 별도 격리 수집하며 로컬 업무 DB를 복사하지 않는다.
- `npm audit --omit=dev --audit-level=moderate`: 취약점 0건.
- 개인 질문·문서·인증정보·실행 DB는 Git 대상에서 제외.

## GitHub 인증 복구와 후속 업로드

브라우저 인증 후 제한된 도구 프로필에서 `hosts.yml` 쓰기와 Windows 보안 저장소 접근에 실패했다. 일반 사용자 권한의 숨김 실행에서 기존 자격증명의 실제 계정이 junthropic이고 저장소 쓰기 권한이 있음을 확인했다. 유효한 인증을 공식 CLI로 junthropic 항목에 다시 등록하여 기본 인증도 복구했다. 토큰을 로그·소스·임시 파일에 저장하지 않았다. 연결 앱 자체의 403 권한은 바꾸지 않았으며, 요청한 저장소 업로드는 복구된 공식 CLI 경로로 완료했다.

아래는 향후 인증이 만료되었을 때의 절차이며 현재 재인증은 필요하지 않다.

외부 콘솔을 새로 띄우지 않고 IDE 통합 터미널에서 진행한다. 비밀번호·토큰을 채팅·파일·Git에 붙여 넣지 않는다.

```powershell
gh auth login --hostname github.com --git-protocol https --web --skip-ssh-key --scopes workflow
gh auth status
```

로그인한 계정이 junthropic인지 확인한다. `repo`·`workflow` 권한은 코드와 `.github/workflows` 업로드에 사용한다. 다른 계정의 인증이나 전역 Git 정책을 삭제하지 않는다. Git 실행 환경이 주입한 잘못된 설정이 있는 경우 해당 실행에서만 초기화한다.

```powershell
$env:GIT_CONFIG_COUNT='0'
git -c credential.helper= -c 'credential.helper=!gh auth git-credential' ls-remote origin
```

원격에 새 커밋이 생겼는지 먼저 확인한다. 비어 있거나 로컬 이력의 조상인 경우에만 `git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push -u origin main`으로 일반 push한다. force push는 사용하지 않는다. 원격 HEAD가 로컬과 같고 CI가 성공해야 업로드 완료로 기록한다.
