# 진행 상태

기준일: 2026-11-02. 앱 버전 0.8.4.0(Microsoft Store 베타, 미제출). 가격은 아직 정하지 않았다.

"만들어짐"은 코드가 있다는 뜻이다. "시험 있음"은 그 동작을 지키는 자동 시험 파일(`tests/`, 60여 개)이 있다는 뜻이다. 어느 쪽도 실제 사업장에서 써 보고 확인했다는 뜻은 아니다.

## 시험 기준선 (2026-11-02, 이 작업 PC)

`npm run check`(빌드 + 전체 시험)를 Claude Code 안에서 돌린 결과다. 빌드(타입 검사, 서버 빌드, 옛 화면 빌드)는 통과했다.

| 항목 | 개수 |
|---|---|
| 시험 파일 | 67개 중 64개 통과, 3개 실패 |
| 시험 | 768건 중 통과 762, 실패 5, 건너뜀 1 |
| 건너뛴 시험 | V8-M07(로컬에서 만든 패키지 폴더가 있을 때만 돈다) |

실패 5건은 모두 이 PC에서 서버를 `127.0.0.1`에 여는 순간 `listen EFAULT` 오류가 나거나, 서버를 띄워 통신하다 시간이 초과된 것이다. 코드 변경과 무관한 환경 문제로 본다(원인은 아직 확정하지 못했다).

환경 때문에 실패할 수 있는 시험 (실행할 때마다 달라진다):

이 시험들이 실패해도 그 자체로 새 문제가 생긴 것은 아니다. 이전 기준선과 비교해서, 위 목록 밖의 시험이 실패하거나 위 시험이 `listen EFAULT`·시간 초과가 아닌 다른 이유로 실패할 때만 새 문제로 본다. 위 시험 중 하나를 고쳐야 할 때는 먼저 Claude 밖 PowerShell에서 같은 시험을 다시 돌려 본다.

GitHub Actions의 `Build and test` 워크플로는 현재 꺼져 있어서(수동 비활성화) 같은 시험을 CI에서 대조하지 못했다. 화면 잠금 시험(V8-U01, V8-W02)은 이번 기준선에서 통과했다.

## 만들어졌고 시험이 있는 것

| 영역 | 내용 |

## 만들어졌지만 기본 앱에 연결하지 않은 것

2~7단계에서 만든 후보 계층(컴플라이언스 평가, 기존 자료 연결, 안전관리자 의무 6가지, 교육 등)은 코드와 시험이 있지만 기본 경로에 연결되어 있지 않다. 안전관리자 미리보기 스위치(기본 꺼짐)만 기본 경로에 닿아 있고 `clear_risk`를 내지 않는다. 연결하려면 풀어야 할 조건이 남아 있다.

## 사람이 확인하지 않은 것

- Store 심사 결과와 심사 의견
- 실제 회사 PC(회사 보안 프로그램, 다른 Windows 설정)에서의 설치·실행
- 법률 전문가의 승인 규칙 검토. 그래서 `clear_risk`를 막아 둔 상태다
- 연결 목록(법제처 1 + 서비스 28) 모두에서 사용자가 키를 발급받아 입력하는 과정이 실제로 매끄러운지

## 남은 일

순서는 사용자가 정한다. 구현이 끝난 뒤 해야 하는 정리는 마지막에 둔다.

1. **남은 보안 위험 고치기**: (가) 같은 PC의 다른 프로그램이 쿠키를 얻으면 세션을 쓸 수 있음(F-02). (나) 실행 토큰 재사용(F-09)은 0.8.4.0에서 고쳤다(1회용 값, 결정 0011, 시험 V8-X13~X24·V8-Q01~Q08). 0.8.3.0·0.8.4.0의 설치 시험·WACK는 아직 돌리지 않았다.
2. **개발자 키 삭제와 법령 갱신 방법 정하기**: 개발자 개인 법제처 키를 지우면 번들 갱신 워크플로가 멈춘다. 지운 뒤 번들을 어떻게 새로 만들지 정해지지 않았다.
3. **연결 목록 개수 맞추기**: 코드는 1 + 28이고 사용자가 말한 숫자(32)와 다르다. 어느 쪽이 맞는지 정하고 코드나 안내문을 맞춘다.
4. **후보 계층 연결 조건 해소**: 기본 표 암호화·소유권 구분, 보호 사례 결과가 평문 표로 복사되는 문제, 내보내기 점검의 빈틈, 수동 보완·독립 검토 화면(화면 잠금을 풀어야 함), 전문가 검토와 활성화. 연결 여부 자체가 사용자 결정이다.
5. **오래된 `docs/` 보고서 정리 방법 정하기**: 2~8단계 보고서, 증빙, 인계 문서는 지금 그대로 둔다. 일부는 시험과 스크립트가 읽는 입력(공문 원본, 계약 표, 화면 잠금 기준 목록, 설치 시험 결과)이므로 옮기기 전에 시험이 읽는 곳을 먼저 정리해야 한다.
6. **구현이 끝난 뒤 개인 흔적 정리**: `.env`의 본인 API 키 삭제, GitHub 비밀값 `LAW_OC` 삭제, 저장소 전체에서 이메일·API 키 같은 개인 흔적 점검·정리. 키를 지우기 전에 2번의 갱신 방법이 정해져 있어야 한다.
7. **가격 결정**: 아직 정하지 않았다. 사용자가 정한다.
8. **로컬 시험 실패 원인 확인**: 위 기준선의 `listen EFAULT` 실패가 이 PC 환경 때문인지 가린다(CI 대조, 보안 프로그램·방화벽 확인).
9. **GitHub Actions 켜기 여부 정하기**: `Build and test`와 MSIX 워크플로가 꺼져 있다.
10. **의존성 보안 점검 14건과 설치 후 스크립트가 실행되지 않은 패키지 2개 처리**: 지금은 기록만 했다.
