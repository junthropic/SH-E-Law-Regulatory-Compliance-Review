# 0011. 설치판 화면 열기는 열 때마다 새 1회용 값을 쓰고, 두 번째 실행은 "화면 열어 줘" 신호만 보낸다

상태: 확정 (2026-11-02, 0.8.4.0)

## 맥락
설치판 런처가 만든 실행 토큰은 서버가 켜져 있는 동안 같은 값이 계속 쓰였다(보안 검토 F-09). 그 값은 `launch.json`에 적혀 있었고 브라우저 주소 조각(`#launch=`)으로 넘어가 브라우저 기록·세션 복원에도 남을 수 있었다. 값을 읽은 같은 Windows 사용자의 다른 프로그램은 서버가 꺼질 때까지 몇 번이고 새 세션을 받을 수 있었다. 베타 화면은 해시로 잠겨 있어(0009) 화면 쪽 동작은 바꾸지 않는 범위에서 고쳐야 했다.

## 결정
- 런처는 시작할 때 만든 **실행 키**를 서버 환경변수로만 넘기고, 브라우저를 열 때마다(준비 직후, 트레이 "화면 열기", 아이콘 두 번 누르기, 다시 실행 신호) 실행 키로 서명한 새 **1회용 값**을 만든다.
- 서버는 값마다 한 번만 받아들이고, 만든 지 **5분**이 지난 값과 1분 넘게 미래 시각인 값은 거부한다. 5분·1분·2초(신호 간격)는 조정할 수 있는 기본값이다.
- `launch.json`에는 값도 키도 적지 않는다(포트·프로세스 번호·통로 이름만).
- 시작 메뉴로 다시 실행하면 새 런처는 값을 받지 않고, 이미 떠 있는 런처에 로컬 통로로 **"화면 열어 줘" 신호만** 보낸다. 값은 통로로 나가지 않는다. 설치 시험을 위한 "값 하나 주기" 요청은 시험용 패키지에만 컴파일된다.
- 거절 문구: "화면 오른쪽 아래 알림 영역의 SH·E 아이콘에서 「화면 열기」를 누르거나, 시작 메뉴에서 앱을 다시 열어 주세요." 거절 이유는 나눠 알리지 않는다.

## 검토한 대안
- 서버 수명 동안 한 번만 받기: 브라우저를 다 닫으면 앱을 껐다 켜야 해서 불편하다.
- `launch.json`에 다음 값을 보관: 파일을 읽은 프로그램이 세션을 얻는다.
- 통로로 값을 돌려주기: 같은 사용자의 아무 프로그램이나 언제든 값을 받는다.
- 시간 제한 없음: 기록에 남은 안 쓴 값이 계속 유효하다.
- 런처가 값을 만들 때마다 서버에 등록: 런처→서버 통로가 새로 필요하고 등록과 브라우저 열기 사이에 경쟁이 생긴다. 서명 방식은 기존 환경변수 하나로 끝난다.

## 결과
- 같은 사용자의 다른 프로그램이라는 위협을 줄이지만 다 막지는 못한다. 브라우저를 띄우는 순간의 주소 가로채기, 화면 열기 신호, 통로 이름 선점, 쿠키 재사용(F-02)이 남는다(`docs/security.md`).
- 브라우저의 첫 실행 설정처럼 5분 넘게 걸리는 경우 사용자는 거절 문구를 보고 다시 열어야 한다.
- 통로가 값을 돌려주게 바꾸거나 Store 패키지에 값 요청을 넣으려면 새 결정이 필요하다.
