# 보안 정책

전제: 한 사람이 자기 Windows PC에서 쓰는 로컬 앱이다. 로그인 계정이 없고, "다른 사용자"는 같은 PC의 다른 Windows 사용자나 같은 사용자의 다른 프로그램이다. 제작자 서버로 나가는 통신은 없다.

## 보호 대상

- 검토 기록(질문, 사실, 쟁점), 업로드 원본과 추출 텍스트, 설정(보존 기간, 동의 상태 등).
- 사용자가 직접 발급한 법제처 인증값(OC), 공공데이터포털 일반 인증키, 도로명주소 승인키, AI 서비스 로그인 토큰.
- 백업 파일, 승인된 검토자 확인서와 규칙.

## 접속 (인증)

설정한 계정이나 비밀번호는 없다. 서버 안에 있는 세션 쿠키(`she_session`)가 그 역할을 하고, 쿠키를 받으려면 아래 검문을 모두 통과해야 한다. 1번은 서버가 열리는 주소이고, 2~7번은 요청마다 이 순서로 다시 검문한다.

1. **루프백만**: 127.0.0.1 밖에서 들어온 연결은 거절한다.
2. **Host**: `127.0.0.1[:포트]` 형식이 아니면 403 ("로컬 주소 127.0.0.1로 접속하세요"). `localhost`나 PC 이름으로는 접속할 수 없다.
3. **Origin**: 있으면 `http://<Host>`와 정확히 같아야 한다. 다르면 403.
4. **경로 판정**: 보안 결정은 라우터가 맞춘 경로(퍼센트 디코딩 후)로 한다. 원본 URL로 판단하지 않는다(`/%61pi/…`로 검문을 건너뛰는 시도를 막기 위해). 디코딩이 안 되는 주소는 400.
5. **교차 사이트**: `/api/` 요청에서 `Sec-Fetch-Site: cross-site`이면 403.
6. **세션**: `/api/bootstrap`만 세션 없이 열린다. 다른 `/api/` 경로는 쿠키가 없거나 모르는 값이면 401 ("화면을 새로고침하세요").
7. **CSRF**: GET·HEAD가 아닌 요청은 `X-CSRF-Token`이 세션에 묶인 값과 같아야 한다. 아니면 403.
8. **실행 토큰(설치판)**: 위 1~7번과 달리 새 세션을 줄 때(`bootstrap`)만 확인한다. 런처가 시작할 때마다 새 난수를 만들어 환경변수로 넘기고, 서버는 읽자마자 환경에서 지운다(자식 프로세스가 물려받지 않게). 브라우저는 주소의 `#launch=` 조각(요청 줄에 실리지 않음)으로 받아 `bootstrap`에 한 번 헤더로 보낸다. 토큰이 틀리면 세션을 주지 않는다("시작 메뉴에서 앱을 다시 열어 주세요"). 설치판이 토큰 없이 시작되면 서버는 포트를 열지 않고 종료한다. 개발 실행·시험에서는 토큰이 없으면 이전처럼 동작한다.

응답에는 항상 `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, 카메라 등 장치 권한 차단, 같은 출처만 허용하는 CSP(`frame-ancestors 'none'`)를 붙인다.

### 허용되지 않는 것

- 다른 PC에서의 접속, 다른 사이트의 요청, 세션·CSRF 없는 변경 요청.
- 진행 중인 변경·검토 작업이 있을 때 다른 변경 요청(409), 종료 중의 모든 `/api/` 요청(503).
- 설치판에서 MCP 조회, 공개 법령 자동 업데이트, 전자민원 연결·수집, 평문 JSON 백업·복원. 각각 403과 안내 문구로 거절한다.

## 저장 암호화

- 대상: 표 `reviews`, `documents`, `settings`의 본문과 업로드 원본 파일. 256비트 AES-GCM이며 태그는 16바이트로 고정한다(짧은 태그는 복호화 전에 거절).
- 설치마다 256비트 데이터 키 하나를 만들고, Windows 사용자 보호(DPAPI)로 감싸서 보관한다. 같은 PC의 같은 Windows 사용자만 열 수 있다. 다른 사용자나 다른 PC에서는 "암호화된 자료를 열 키가 없습니다"로 실패하며 평문으로 대신 열지 않는다.
- 표 이름+ID(파일은 파일 이름)를 인증 데이터로 묶어서, 암호문을 다른 행이나 파일로 옮기면 열리지 않는다.
- 시작할 때 기존 평문 자료를 암호화 저장으로 옮긴다(`storage_encrypted` 기록).
- **암호화하지 않는 것(현재 설계)**: 공개 법령 자료(`evidence` 표 등)와 일부 기록은 평문이다. 공개 자료이므로 범위를 의도적으로 좁혔다.
- 업로드 원본 파일 이름은 `^[A-Za-z0-9-]+\.[a-z]+$` 형식만 허용한다(경로 이탈 방지).

## 외부 통신

- 허용 목록: `law.go.kr`(하위 도메인 포함), `apis.data.go.kr`, `www.data.go.kr`, `business.juso.go.kr`, `www.moel.go.kr`, `www.gg.go.kr`, `www.hscity.go.kr`. AI는 `api.openai.com`, `auth.openai.com`. 루프백은 통과. 그 밖의 호스트는 연결을 열기 전에 거부한다(`EgressBlocked`).
- 서버 시작 직후 `fetch`와 `http(s).request`를 감싸 모든 호출이 이 목록을 지나게 한다. 공개 호스트는 https만 허용한다. 리다이렉트는 한 단계씩 직접 따라가며 매 단계의 주소를 다시 검사하고, 호스트가 달라지면 `Authorization`·`Cookie` 등 자격 정보를 떼어낸다. 최대 20단계.
- 요청 본문이 폼 형식(`URLSearchParams`)이면 그 텍스트를 승인된 미리보기와 비교한다. 스트림·바이너리 본문은 AI로 보낼 수 없다.
- 전자민원(epeople) 호스트는 허용 목록에 없다. 민원 수집은 별도 브라우저에서 돌았고 설치판에서는 꺼져 있다.
- 제작자 서버·분석·원격 오류 수집으로 나가는 경로는 없다.

### AI 전송 동의

- 기본은 꺼져 있다. 켜면 동의 시각을 기록한다. 철회하면 대기 중인 전송을 모두 취소한다.
- 설치판에서는(개발 실행·시험·격리 빌드는 아래 참고) AI로 나가는 내용마다 화면에서 보낼 내용을 확인하고 승인해야 하며, **승인 한 번은 전송 한 번**이다. 10분 안에 승인하지 않으면 전송하지 않는다.
- 전송 기록(`v8_ai_send_log`)에는 시각·호스트·방식·바이트 수·해시·결과만 남기고 내용은 남기지 않는다.
- 설치판이 아닌 실행(개발 실행, 테스트, 격리 빌드)에서는 이 승인 관문이 없고 외부 통신 가드만 걸린다.

## 인증키·토큰 관리

- 법제처 OC와 공공 API 키는 사용자가 직접 발급해 설정 화면에 입력한다. 개발자 개인 키를 앱이나 저장소에 넣어 배포하지 않는다. 환경변수 `LAW_OC`는 개발·수집용 보조 경로다.
- 저장소는 보호 저장소(Vault): Windows에서는 DPAPI 사용자 보호, `SHE_EPHEMERAL_AUTH=1`이나 시험에서는 메모리 안에만 둔다(프로세스를 끄면 사라짐).
- 저장 직후 다시 읽어 같은지 확인한다. 같지 않으면 저장 실패로 처리한다.
- 다른 키가 이미 저장된 서비스에 새 키를 넣으면 409로 거절하고, 사용자가 교체를 명시 승인해야 덮어쓴다.
- 삭제하면 보호 저장소에서 지운다. 키·토큰·OAuth 응답은 로그·Git·감사 기록에 넣지 않는다.
- AI 서비스는 ChatGPT 로그인(OAuth)으로 연결한다. 로그아웃하면 토큰을 폐기한다.

## 백업

- 암호화 백업(`/api/beta/backup`): 백업마다 새 256비트 키로 gzip한 뒤 AES-GCM으로 암호화하고, 그 키를 Vault로 감싸 파일에 넣는다. 만든 Windows 사용자 계정에서만 복원된다. 인증키·설정·감사 기록은 들어가지 않고, 앱에 포함된 공개 법령 초기 자료도 뺀다(검토에 쓰인 근거는 검토 기록과 함께 간다).
- 복원은 형식·태그 길이·인증 태그를 검증하고 실패하면 400. 압축 해제 크기는 512MB, 요청 본문은 200MB로 제한한다. 진행 중인 작업이 있으면 409.
- 기존 평문 JSON 백업은 개발 실행에서만 동작한다. 설치판은 끈다.

## 감사 기록 (감사 표에 남기는 사건)

법제처 OC 저장, 공공 API 키 저장, OAuth 연결, AI 전송 동의·철회, AI 전송 승인·거부, 근거 승인(검토자·지역·기준일·해시), 자가 검토, 자동 수집 켜기·끄기·실행, 공개 번들 가져오기·업데이트, 공개 API 가져오기, 저장 암호화 이전, 백업 내보내기·복원, 내보내기 점검, 공개 갱신 오류, 전자민원 세션 시작(개발판), 보존 삭제(삭제 기록 표).

기록에는 본문·키·파일 이름·경로를 넣지 않는다. 오류 메시지는 `safeMessage`로 데이터 폴더 경로와 키 형태 문자열을 가린 뒤 로그·응답에 쓴다.

## 하위 프로세스

- 자식 프로세스에는 허용 목록에 있는 환경변수만 넘긴다. PowerShell은 신뢰된 시스템 경로의 실행 파일만 쓴다.
- Windows에서 보이는 콘솔 창을 열지 않는다(`windowsHide: true`).

## 알고 감수한 위험

- **쿠키 재사용**: 같은 PC의 다른 프로그램이 브라우저 쿠키를 얻으면 그 세션을 쓸 수 있다. 이번 버전에서는 고치지 않고 다음 버전에서 고친다.
- **실행 토큰 재사용**: 토큰이 서버가 켜져 있는 동안 재사용된다. 시작 정보 파일과 브라우저 기록에 조각이 남을 수 있으며, 읽을 수 있는 범위는 같은 Windows 사용자다. 다음 버전에서 고친다.
- **공개 자료 평문 저장**: 위 "암호화하지 않는 것"과 같다.
