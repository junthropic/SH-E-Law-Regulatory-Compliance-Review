# 전체 개발 과정과 업로드 범위

작성 기준: 2026-10-09. 업로드 대상은 `junthropic/SH-E-Law-Regulatory-Compliance-Review`입니다.

이 문서는 지금까지의 사용자 요구, 구현 방향, 정정, 시험과 남은 작업을 연결하는 색인입니다. 실제 존재하는 소스·첨부 명세·보고서·공개 원문·시험 로그와 기존 Git 이력을 함께 보존합니다. 대화에서 확인할 수 있는 흐름을 정리한 기록이며, 접근할 수 없는 과거 답변을 포함한 대화 전체의 원문 내보내기를 뜻하지는 않습니다. 이전 보고서의 완료 주장은 당시 범위의 기록으로 남기며, 최신 미완료 상태를 대체하지 않습니다.

## 요구사항과 의사결정의 흐름

1. 제조업과 위험 작업장의 환경·안전·보건 담당자가 자연어로 상황을 설명하면 국가 법령, 세부 조례, 조문·예외, 공개 국민신문고 회신과 연결 자료를 찾는 서비스를 요청했습니다. 최초 저장소는 `junthropic/SH-E-Law-Check`였습니다.
2. 단순 키워드 검색뿐 아니라 질문에서 사실 후보를 추출하고 지역·기준일·물질·수량·업무에 맞는 자료를 연결하도록 했습니다. 결과는 명확한 법률 리스크, 실무자 판단 필요, 추가 자료 필요로 구분합니다. LLM 결론이나 허가 서류 미제공만으로 위반을 확정하지 않습니다.
3. 법제처 OC, GitHub 인증과 Actions Secret, ChatGPT 연결과 유지 검증을 진행했습니다. 과거 403·인증 만료와 저장 문제를 다뤘습니다. 실제 인증값·OAuth 세션과 Secret은 이 저장소에 포함하지 않습니다.
4. 화성시/경기도 소량위험물 저장·취급을 우선 사례로 정했지만 실제 사업장과 보유자료는 제공되지 않았습니다. 지역·업무 선택은 실제 공정·허가·수량의 확인이 아닙니다. 이 사례는 수집 경로 및 가상 사례 검증으로 한정합니다.
5. 초기 법령조회 API 카탈로그, 공공데이터 목록, 파이프라인 가이드와 `ehs_lookup` 예제를 검토했습니다. 보존본은 [initial-inputs](initial-inputs/)에 있으며 입력 출처와 해시는 [input-origin-manifest.json](input-origin-manifest.json)에 있습니다.
6. 질문→결과, 자료 연결, 검증 통과 조건, 오판 방지의 네 흐름과 구조적 보완을 조사했습니다. 기준일, 별표·부칙, 캐시, 인증값이 들어간 로그·링크 처리를 검토하고 기존 질문과 별도로 200개 추가 질문을 작성했습니다. 초기 설계·감사·질문 파일은 [early-deliverables](early-deliverables/)에 있습니다.
7. 사용자가 지정한 UI/UX 자료를 참고한 디자인 변경을 진행한 뒤, 사용자의 구체적 화면 지시에 따라 문구·버튼·배치와 모델 선택 기능을 수정했습니다. 최신 지시는 UI/UX·문구·동선 동결입니다. 이번 업로드는 화면을 변경하지 않습니다.
8. 최초 6개는 공개 질의응답, 위험물, MSDS, 안전보건법령 스마트검색, 화학물질, KOSHA GUIDE였습니다. 추가 12개 및 설비·인허가 대조 14개를 등록하여 총 32개 서비스로 확대했습니다. 신청 링크·용도·저장·교체·삭제·실제 API 연결 체크를 다뤘습니다. 초기 6개/추가 26개와 실제 연결·공식 명세 검증 범위를 구분합니다.
9. 키 저장 후 연결 체크 표시, 삭제 후 숨김, A01 등록 전용 표시, A08/B07/B08 실패, 검색 중 남는 오류 메시지 등을 수정했습니다. A07의 느린 응답은 별도 신뢰성·호출 조건 조사 대상으로 유지했습니다. 사용자가 연결 완료라고 알린 사실과 이 단계에서 실제 키로 전수 재호출한 사실은 다릅니다.
10. 로컬 저장과 외부 전송, 개인정보·공공 API 이용 조건, 보유 회신 업로드, 검토 확인서, 공개 법규 가져오기, 백업·복원을 설명하고 관련 기능을 보강했습니다. 회신 업로드는 사용자가 가진 자료를 근거 후보로 쓰는 기능이며 승인되지 않은 계정 자동수집은 활성화하지 않습니다.
11. 공보·법령정보의 버전 불일치, 별표·별지 원본 누락, 수집 한도, OCR 및 위임·예외 검토의 미완료를 정정했습니다. `verified=false`와 같은 상태는 실무자용 검토 결과에서 한국어로 설명하도록 했습니다. 출처·버전·시행일·수집일과 확보하지 못한 원본을 구분합니다.
12. 법령 원본과 공식 공보가 다를 때 무조건 최신이라고 간주하거나 반복 다운로드 성공을 법적 검증으로 바꾸지 않는 방향을 정했습니다. 이전 완료 주장과 실제 확인 결과를 대조하고 미확인·충돌·수집 실패를 보존합니다.
13. 앱 접속 거부 복구와 숨김 감시를 다뤘지만, 이후 사용자가 주기 감시를 중단하고 수동/3시간 이상 대화 공백 후 재개 시 확인을 요청했습니다. 최신 개발 지시에서는 운영 앱·DB·4317 접근 자체가 금지됩니다. 이번 업로드도 접속 확인·복구·재시작을 실행하지 않습니다.
14. 화학물질 EHS 자료·자동갱신 기준 및 상세 구현 명세를 참고자료와 규칙·설계 기준으로 채택했습니다. 첨부의 주장과 구현·시험 사실은 분리하며, 중복 프롬프트를 반복 실행하지 않습니다.
15. v2→v3→v4→v5→v6를 순서대로 재사용하여 격리 구현·검증을 확장했습니다. 각 버전 본문은 조사·정정 자료, 부록은 해당 버전의 한 차례 실행 지시로 적용했습니다. 운영 배포·실제 키·실자료·법적 규칙 활성화 금지와 동결 계약을 유지합니다.
16. 이번 요청은 지금까지의 개발 내용을 새 GitHub 저장소에 보존하는 것입니다. 기존 14개 커밋의 이력과 미커밋 구현·보고서·실패 기록을 함께 전달하고 기존 저장소의 이력을 강제로 덮어쓰지 않습니다.

## 버전별 실제 근거

| 단계 | 보존 기록 | 범위 |
|---|---|---|
| 초기 구현·연결·공개 수집 | 기존 Git 이력, `early-deliverables`, `data/public`, 기존 `docs` | 당시 실제 연결 결과와 이후 정정 기록을 함께 보존 |
| 상세 설계·채택 상태 | [specifications](../specifications/) | 첨부 원문, 구현 범위와 미검증 구분 |
| v2 | [implementation-v2](../implementation-v2/) | 기준선, API 등록부, 정책 후보, 시험·gate |
| v3 | [implementation-v3](../implementation-v3/) | 내구성·권한·보호·수집·정책 및 공식 근거 |
| v4 | [implementation-v4](../implementation-v4/) | 원문 첨부·파생 통제·operation 분모와 연결 |
| v5 | [implementation-v5](../implementation-v5/) | 공식 표본·실무 경로·복원·전송 근거 |
| v6 | [implementation-v6](../implementation-v6/) | 교육 5개, 첨부·전송 경로, 이관 재개, 복원 장애, 공식 명세 대조 |

버전별 `execution`, `test-inventory`, `source-manifest`, `build-verification`, `failure-record`, `release-gate`와 `logs`를 읽어 실제 실행과 선언을 대조해야 합니다. 실패한 재시도 기록도 삭제하지 않습니다. v6 시험은 그 당시의 미커밋 소스 digest를 대상으로 했으며 이번 업로드 커밋을 과거 시험 대상으로 소급 표기하지 않습니다.

## 최신 확인 결과와 남은 범위

- v6 최종 시험 **565/565**, 기존 **404/404** 보존, 추가 161개입니다. 브라우저 흐름은 기존 9개+교육 1개이며 교육 5개 시나리오를 포함합니다. 업로드 준비에서 v6 audit을 다시 통과했고 공개 번들 225개의 형식·출처·해시·검증 상태 검사를 통과했습니다.
- 동결 29개 파일 변경 0, v6에서 shared 신규 0과 동기 응답 계약 보존입니다. 이전 단계에서 승인된 변경까지 제거하는 의미는 아닙니다.
- 기존 43개 정책의 실행 후보 12→17, 미구현 31→26입니다. 추가 2개는 별도입니다. 전문가 승인·실제 법률 규칙 활성화는 0입니다.
- 32개 서비스/52개 operation 분모를 보존합니다. 공식 typed/wrapper 모델은 44/52, 추가 7개는 공식 입출력 표이며 완전한 모델로 승격하지 않았습니다. v6에서 실제 키·실응답 검증은 0입니다.
- v6에서 명시한 기술 하위 점검 101개 중 미검증 99→8, 신규 확인 91입니다. 이는 전체 잔여 업무 또는 12개 큰 gate의 완료율을 뜻하지 않습니다.
- 정부 원본 2건은 HTTP 200이어도 실제 내용이 HTML 오류이므로 원본 확보 실패를 유지합니다. 이미지형 별표 OCR·결정적 셀 원본 대조, 수집 한도 밖 첨부, 전체 위임·예외의 현장 적용은 미완료입니다.
- 실제 사업장 자료·권한자·전문가 정답셋 분모는 0이며 정확도는 산출하지 않았습니다. 가상 사례·합성 시험 성공을 실사업장 적합성이나 법률 승인으로 표현하지 않습니다.
- 미등록 legacy/private 전체 보호 이관, 실제 디스크 부족·Windows ACL·전원 차단, directory fsync, alias/TOCTOU 전수, provider 공식 quota/reset 조건 등은 남습니다. 12개 큰 gate를 지우거나 완료로 바꾸지 않았습니다.

## 포함·제외와 복원 안내

포함: 애플리케이션과 테스트 소스, 잠금 파일·설정·실행 스크립트, 초기 설계/질문/카탈로그/예제, v2~v6 첨부 명세와 보고서, 공식 공개 원문·공개 번들, 검토한 격리 개발 로그, 기존 Git 커밋입니다. 원본 파일별 해시는 `publication-manifest.json`에서 확인합니다. 격리 개발 로그는 기존 `*.log` 제외 규칙의 예외로 해당 문서 경로만 명시적으로 포함합니다.

제외: `.local`, 실제 인증키·토큰·세션·환경파일, 개인 업무 DB·자료 업로드·민원·비공개 백업, `node_modules`, 생성 build/dist, 재현 가능한 격리 작업 디렉터리와 중복 소스 zip/bundle입니다. 실제 데이터가 없어서 누락된 현장 사실을 만들어 넣지 않습니다. 테스트용 TLS 키는 `tests/fixtures/v5-tls`의 합성 localhost fixture이며 실제 서비스 키가 아닙니다. 임시 디렉터리 자체 대신 결과·실패 로그와 소스 해시를 보존합니다.

GitHub Secret·OAuth와 로컬 보호 저장 인증값은 Git 이력이나 새 저장소로 이전되지 않습니다. 저장소 업로드는 운영 앱의 이전·배포·재시작 또는 공공 API 재연결을 실행하는 작업이 아닙니다. 기존 예약 수집 workflow의 정의는 보존하되 이번 작업에서 수집·실제 키 사용을 실행하지 않습니다.

원본 대화의 접근 가능한 첨부·자료와 작업 흐름을 보존했으나, 이 저장소를 채팅 시스템의 완전한 원문 백업이라고 부르지 않습니다. 향후 대화 원문 export가 제공되면 별도의 검토 후 이 색인에 연결할 수 있습니다.
