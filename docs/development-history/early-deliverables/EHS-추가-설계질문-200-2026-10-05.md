# EHS 서비스 추가 설계 질문 200개

작성일: 2026-10-05. 개발·수정 작업을 멈춘 상태에서 작성한 설계 검토용 질문집이다. 질문은 미결정 사항을 드러내기 위한 것이며, 언급된 기능의 구현 완료나 특정 법적 결론을 뜻하지 않는다.

중복 대조 범위는 이 대화의 질문·흐름도, 첨부자료 개발계획, 통합 점검서, 저장소 설계·검토자·검증 문서와 화성시 운영검증안이다. 이미 다룬 기준일 분리, 시군구 조회, 별표 누락 확인, 0건과 오류 구별, 단위 환산, 인증값 제거 같은 일반 질문을 재수록하지 않고, 그 아래의 새로운 결정 단위와 모듈 사이 경계 상황을 질문한다. 제공되지 않은 별도 질문집은 대조 범위에 포함하지 않는다.

20개 모듈 묶음에 10개씩, Q001–Q200으로 구성한다. 화살표는 데이터·책임의 연결을 뜻하며 무조건 순차 실행한다는 의미는 아니다. 추가 모듈은 논리적 기능 단위의 후보다. 별도 서버나 새로운 외부 서비스 가입을 전제하지 않는다. 실제 외부 자료원은 사용하기로 확정한 범위를 유지한다.

## M01. 검토 대상과 의무 주체 — Q001–Q010

**Q001 · 같은 주소의 여러 사업자**  
같은 건물에서 원청·도급업체·창고 운영사가 각각 다른 업무를 수행할 때, 주소를 공유한다는 이유로 사실과 의무가 합쳐지지 않도록 어떤 사업자·계약 관계를 검토 대상 식별자에 포함해야 하는가? **연계: M01→M03→M13.**

**Q002 · 설비 소유자와 실제 운영자**  
설비 소유·임차·운전·정비 주체가 서로 다르면 하나의 설비에 여러 책임 후보를 어떻게 연결하고, 주체를 정하지 못한 의무만 따로 미결정 상태로 유지할 것인가? **연계: M01→M13→M18.**

**Q003 · 사업장 식별번호의 역할**  
사업자등록 단위, 공장 등록 단위, 내부 관리 사업장 단위가 일치하지 않는 경우, 사용자가 입력한 번호 중 무엇을 식별 보조값으로만 쓰고 무엇을 법적 검토 단위로 채택할 것인가? **연계: M01→M04→M14.**

**Q004 · 공유 방지시설의 서비스 범위**  
여러 공정이 한 방지시설을 공동 사용하면 시설 전체의 사실과 특정 공정의 사실을 어떻게 나누며, 한 공정의 변경이 다른 공정의 검토까지 영향을 주는 연결 조건은 무엇인가? **연계: M01→M09→M15.**

**Q005 · 이동식 설비와 임시 작업장**  
이동식 탱크·임시 저장장소처럼 대상이 이동할 때 고정 설비 ID와 위치 이력을 어떻게 연결하고, 이동 전후 검토가 같은 대상의 연속 사건임을 어떤 방식으로 표현할 것인가? **연계: M01→M05→M15.**

**Q006 · 교대조별 다른 운영 상태**  
주간에는 생산하고 야간에는 세척·정비하는 설비를 하나의 평균 운영 상태로 저장하지 않으려면, 설비 등록과 작업 시나리오 사이에 어떤 관계를 두어야 하는가? **연계: M01→M02→M12.**

**Q007 · 명칭 변경과 대상 교체**  
사용자가 ‘1호 저장소’를 ‘A동 창고’로 바꿨을 때 단순 별칭 수정인지 실제 위치·설비 교체인지 확인하고, 기존 증빙의 연결을 유지하거나 끊는 기준을 무엇으로 정할 것인가? **연계: M01→M03→M15.**

**Q008 · 사업 양수도와 인허가 승계**  
설비·주소는 같지만 운영 사업자가 바뀐 사건에서, 과거 인허가 문서를 새 운영자의 유효한 증빙으로 바로 연결하지 않도록 승계 사실을 어떤 별도 관계로 표현할 것인가? **연계: M01→M03→M13.**

**Q009 · 단지 공통 사실의 상속**  
산업단지나 사업장 전체의 정보를 여러 개별 시설이 공유할 때, 공통값과 시설별 예외값 중 어느 값이 사용됐는지 남기고 공통값 수정의 영향을 제한하는 규칙은 무엇인가? **연계: M01→M03→M14.**

**Q010 · 의도적으로 제외한 공간**  
사용자가 ‘이번에는 A동만 검토’라고 정했는데 B동과 배관·저장·배출이 연결되어 있다면, 제외 범위를 존중하면서도 검토에 반드시 필요한 연결 부분을 드러내는 경계 규칙은 무엇인가? **연계: M01→M02→M10.**

**Q013 · 문장 중간의 자기 정정**

**Q014 · 부정 범위의 해석**

**Q015 · 지시어가 가리키는 대상**

**Q016 · 반복 질문의 정보 효율**

**Q019 · 기밀 사실의 대체 입력**

## 질문을 설계 결정으로 바꾸는 기록 형식

각 질문의 답변은 ‘결정 내용 / 결정 이유 / 주 담당 모듈 / 영향받는 모듈 / 입력·출력 계약 / 실패·미확인 처리 / 검증 사례 / 보류 사유’로 기록하면 개발 항목으로 전환할 수 있다. 모든 질문이 곧 신규 기능 개발을 뜻하지는 않는다. ‘이번 범위에서는 지원하지 않음’도 이유와 사용자에게 보여줄 상태가 정해져 있으면 유효한 결정이다.

추가 모듈 후보 중 여러 질문의 공통 기반이 되는 것은 검토 대상 관계 등록(M01), 업무 용어 연결(M04), 자료원 계약 관리(M06), 문서 구성요소 관리(M08), 법령 관계 관리(M09), 데이터 계약·이벤트 관리(M14), 검토 분기 관리(M15), 전문가 의견 관리(M17), 품질 평가 자료 관리(M19)다. 기존 기능 안에 통합할지 독립 모듈로 둘지는 이 질문들의 답과 실제 규모를 보고 결정한다.

## 중복 검토 기록

- 질문 번호 200개, 모듈 묶음 20개, 묶음별 10개를 확인했다.
- 질문 제목 및 질문 본문의 완전 일치 중복은 없으며, 모든 질문에 둘 이상의 모듈 연결을 표기했다.
- 기존 문서와의 표현 유사도 검색은 검토 보조로 사용했고, 기존의 일반 점검 내용을 다시 묻거나 새 질문 사이에서 같은 결정을 반복하는 항목은 내용 검토로 수정했다.
- 같은 모듈이나 용어가 반복되는 것은 모듈 간 연관성을 다루기 위한 것이다. 각 질문의 구분 기준은 표현의 차이가 아니라 답변으로 결정할 대상·경계 상황·모듈 책임의 차이다.
