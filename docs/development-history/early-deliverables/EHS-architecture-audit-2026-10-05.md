# EHS 조회·검증 흐름 통합 점검

점검일: 2026-10-05, 한국 시간. 대상: SH-E-Law-Check, 커밋 `e770bde` 및 대화에서 작성한 네 가지 목표 흐름도.

**결론: 네 흐름도는 업무 방향을 설명하지만, 아직 실제 동작을 규정하는 완결된 설계는 아니다. API 연결뿐 아니라 질문에서 조회 계획을 만드는 과정, 쟁점별 근거 완전성, 예외 평가, 판정 상태, 변경 영향 추적을 연결해야 한다.**

이번 작업은 코드·설계 점검이다. 운영 코드, 개인 DB, 인증정보, 실제 사업장 자료는 수정하지 않았다. 법률 해석이나 실사업장 위반 여부를 판정하지 않았다. 아래의 P0는 잘못된 결론·정보 노출을 방지하거나 자연어 검토의 핵심 약속을 충족하기 위해 우선 해결할 항목, P1은 시범 운영 전 완성할 항목, P2는 확장·운영 품질 항목이다.

## 1. 확인 방법과 한계

- 서버·자료형·화면·수집/승인/공개 배포 경로와 기존 테스트를 읽었다.
- 빌드 성공. 기존 자동 테스트 89개 통과, 1개 건너뜀. 건너뛴 항목은 Windows DPAPI 사용자 프로필을 사용하는 저장소 왕복 시험이다. 이번 결과로 실제 OC·ChatGPT 인증 유지가 확인된 것은 아니다.
- 별도 합성 DB와 가짜 인증 문자열로 14개 관찰 조건을 재현했다. 이 숫자는 서로 독립적인 결함 14개나 실제 피해 14건을 의미하지 않는다.
- 공식 API 실호출, 실제 국민신문고 회신 수집, 원문 법적 적합성 검토, 운영 브라우저 E2E, GitHub 예약 실행 여부는 이번 점검 범위에 포함하지 않았다.
- 저장소 소스 변경은 없으며 점검 후 Git 작업 상태도 깨끗하다. 빌드 산출물과 별도 점검 자료만 생성했다.

## 2. 이미 있는 보호장치와 남은 연결

| 흐름 | 확인된 기존 기반 | 아직 연결되지 않았거나 불충분한 부분 |
| --- | --- | --- |
| ① 질문 → 결과 | 자연어 입력, 지역·기준일, 추가 답변, 모델 분석, 결과 기록 | 질문에 따른 수집 계획, 분야별 동적 질문, 사실 확인 상태, 보완 검토의 계보 |
| ② 자료 연결 | 법제처 HTTPS 수집, 현행/연혁 목록, 시행일 확인, 원문 저장, 일부 첨부 추출 | 시·군·구 실조회, 위임·준용 관계 탐색, Q&A 전용 연동, 자료 역할별 검색·날짜 모델 |
| ③ 검증 → 분류 | 원문 인용 문자열 확인, 모델의 clear_risk 차단, 승인 규칙, 검토 전체의 완전성 제한 | 규칙 미실행과 불충족 구분, 복합 조건·예외 계산, 쟁점별 검증, 단정적 설명 제어 |
| ④ 오탐 방지 | 미확인/누락 표시, 수집 실패 시 이전 자료 보존, 기존 출처 버전 변경 시 재검토 표시 | 새 법규·규칙·첨부 변경 영향, 미확인 답변의 구조화, 원본까지 결속한 승인, 누락된 의무 탐지 |

기준일·캐시·로그 보호가 전혀 없는 것은 아니다. 한국 날짜 처리, 시행 버전 선택, 24시간 신선도 검사, 일부 인증값 제거, DPAPI, 로컬 호스트·CSRF 검사, 공개 수집 DB 분리는 구현되어 있다. 보완 지점은 이 장치들이 모든 자료 유형·판정 경로·출력 경로에 일관되게 적용되지 않는다는 데 있다.

## 3. 상세 발견 사항

### F01 — P0: 자연어 질문에서 조회 계획으로 넘어가는 단계 부재

**코드 확인.** 현재 수집은 국가 자료에서 위험물안전관리법과 위험물 행정규칙, 지역 자료에서 시·도 이름과 위험물 검색어를 사용한다. 검토 검색에도 고정된 위험물 단어가 추가된다. 모델의 역할 설명과 기본 추가 질문도 위험물 중심이다. 따라서 MSDS·폐기물 질문을 입력했다고 그 분야의 필요한 법령을 자동 수집하는 구조는 아직 아니다. MCP 탐색 도구도 별도 조회 기능이며 자연어 검토의 자동 수집·근거 확정 경로와 연결되어 있지 않다.

**보완:** 모델 분석 전에 `검토 계획`을 생성한다. 계획에는 쟁점 ID, 사용자가 요청한 범위, 확인된 지역·기준일, 필수 사실, 법령 후보, 필요한 자료 유형, 활성화된 자료원, 제외/지원하지 않는 범위를 둔다. 법령 후보는 공식 식별자로 확인하고, 모델이 임의 URL이나 미등록 자료원을 호출하도록 하지 않는다. 1차 지원 범위 밖의 질문은 해당 사실과 필요한 다음 단계를 표시한다.

### F02 — P1: 검색 순위와 실제 관련 자료 선별이 분리되지 않음

**합성 재현.** 전혀 일치하지 않는 검색어에도 지역·기준일에 맞는 저장 자료가 반환됐다. 현재 전문 검색은 순위를 만드는 용도이고, 최종 반환은 해당 지역의 자료 전체에 가깝다. 검색어는 3자 이상 단어 중 앞 25개에 제한된다. 긴 질문의 뒤쪽 핵심 쟁점이나 한국어 표현 차이가 누락될 수 있다.

**보완:** 정확한 법령·조문 식별, 동의어/업무 용어 검색, 관계 탐색을 결합한다. 직접 근거·유사 참고·무관 자료를 분리한다. 순위 밖으로 밀린 필수 별표나 예외는 강제 포함한다. 결과 없음, 실행 실패, 인증 미승인, 한도 도달, 일부 조회를 서로 다른 상태로 반환한다. 검색 상한에 도달하면 미조회 범위를 기록한다.

### F03 — P0: 자연어 답변을 사실 확인으로 간주하는 기준이 약함

**합성 재현.** `확인 예정`, `자료 없음`, `아마 10`, `검토 예정`이 현재 함수에서는 확인된 답변으로 처리된다. 일부 미확인 단어를 제외하고 빈 값이 아니면 확인한 것으로 보기 때문이다. 반대로 긴 설명 안의 부정 표현 때문에 다른 확정 사실까지 미확인으로 볼 수도 있다. AI가 추출한 사실은 미확인으로 유지하지만 이를 사용자 확인·수정으로 승격하는 일관된 사실 모델은 없다.

**보완:** 사실마다 `미입력 / 사용자 진술 / 증빙 대조 / 불명 / 상충 / 적용 제외` 상태, 확인 주체·시각·원문 위치를 둔다. 문장 존재 여부로 확인 상태를 결정하지 않는다. 수량은 값·단위·물질·구역·측정 기준을 분리한다. 허가증 미첨부와 허가 미취득은 별개 값이다. 자료 부족을 규칙의 false로 변환하지 않는다.

### F04 — P0: 시·군·구는 입력받지만 법적 적용 범위에 충분히 반영되지 않음

**코드 확인.** 자료 수집은 조례 제목이 시·도 이름으로 시작하는지 확인한다. 시·군·구 이름으로 시작하는 조례가 이 경로에서 제외될 수 있다. 검색·규칙 평가의 지역 비교는 시·도 단위이며, 시·군·구는 주로 화면과 승인 키에 사용된다. 고정 시·도 목록도 기준일별 관할 관계를 표현하지 않는다.

**보완:** 행정구역 코드, 상하위 관할, 명칭 변경과 유효기간을 저장한다. 사업장 위치에서 적용 관할을 구하고, 관계 조문에서 어떤 자치단체의 규정이 필요한지 확인한다. 시·도 규칙을 다른 시·군·구의 개별 규칙과 혼용하지 않는다. 승인 규칙에도 관할 범위를 결속한다. 화성시 관련 규정이 실제 필요한지는 위임·적용 범위로 확인하며 무조건 존재한다고 가정하지 않는다.

### F05 — P0: 기준일은 있으나 조문·행위·회신의 시간 모델은 부족

**코드 확인.** 한국 날짜 처리와 문서 단위 시행일 선택은 있다. 그러나 조문별 다른 시행일, 부칙의 경과조치, 설치·허가·변경일에 따라 달라지는 적용법을 문서 단위 날짜만으로 판단할 수 없다. 현재 시행 시작일 필터를 해석례·민원에도 그대로 사용하면 시행일 없는 회신이 사라질 수 있다. 같은 시행일의 다른 공포 버전은 뒤 공포 버전을 우선하는 선택이므로, 질문이 ‘당시에 알 수 있었던 자료만 사용’인지도 구분해야 한다.

**보완:** 최소한 검토 기준일, 현장 행위일, 공포일, 조문별 시행기간, 수집/확인 시각, 회신일을 분리한다. 원문 현재 버전과 기준일 적용 버전을 각각 표시한다. 날짜 미상에 임의 기본일을 넣지 않는다. 미래 시행, 과거 사건 재검토, 경과조치의 시간축을 정하고 기간 끝점 포함 여부도 일관되게 정의한다. 실제 응답의 법령 ID·버전 ID·시행일을 함께 검증한다.

### F06 — P0: 규칙의 불충족·미평가·적용 제외가 같은 결과

**합성 재현.** 위반 조건 불충족과 규칙 미승인이 모두 `undefined`를 반환한다. 자료 부족, 예외 미확인, 근거 불일치도 같은 경로다. 앞선 흐름도의 ‘아니요 → 확인된 리스크 없음’은 이 구분 없이는 구현하면 안 된다.

**코드 확인.** 규칙 조건은 단일 비교이고, 예외는 문자열 `해당 없음`과 비교한다. 필수 사실은 존재·확인 여부만 검사한다. 예를 들어 ‘수량 조건 충족 AND 필요한 신고 미이행’ 같은 복합 위반 요건은 별도로 표현해야 한다. 수량 계산 API는 존재하지만 계산 근거와 결과가 검토 사실·규칙에 자동 연결되지 않는다.

**보완:** 평가 상태를 `위반 조건 일치 / 조건 불충족 / 적용 제외 / 미평가 / 오류`로 분리하고 이유 코드를 남긴다. AND·OR·NOT·기간·단위·합산 구역·복수 예외를 표현한다. 법적 의무의 발생과 실제 의무 불이행을 별도 단계로 평가한다. 각 계산에 적용 조문·지정수량 출처·입력과 단위·계산 버전을 결속한다. 최종 화면의 기존 세 분류는 유지하면서 내부 평가 상태를 추가한다.

### F07 — P0: 분류를 낮춰도 단정적인 결론이 남을 수 있음

**합성 재현.** 모델이 `clear_risk`와 단정적인 결론을 보내면 분류는 `human_review`로 바뀌지만 결론 문장과 심각도는 유지된다. 원문에 8자 이상 문구가 존재하면 인용 검사를 통과할 수 있으나, 이는 해당 문구가 주장 전체를 뒷받침하거나 적용 범위가 맞다는 증거가 아니다. 유효하지 않은 인용을 제거하는 경우에도 다른 설명 필드의 근거 없는 내용까지 자동 검증하는 것은 아니다.

**보완:** 결과의 주장마다 근거·적용 사실·예외 판단을 연결한다. 모델 초안은 내부 상태로 두고, 검증 결과로 최종 결론·조건·심각도·조치 문구를 다시 구성한다. `human_review` 상태에 위반 확정 표현이 남지 않게 한다. 재검색/수정에 실패하면 보류 이유를 표시한다. 다른 LLM의 동의만으로 법적 검증 완료로 승격하지 않는다.

### F08 — P0: AI 입력이 조문 중심이 아니라 문서 앞부분 잘라내기

**합성 재현.** 법규 본문은 문서당 최대 18,000자, 전체 90,000자 범위에서 앞부분을 가져온다. 뒤쪽의 예외가 빠지는 경우를 재현했다. 생략 사실은 보고되므로 조용한 누락은 아니지만, 긴 법령일수록 검토가 계속 보류되는 구조다. 자료를 더 많이 연동하면 문제도 커진다.

**보완:** 쟁점과 연결된 조문·정의·위임 조문·별표 행·예외·부칙을 묶어 가져온다. 표의 머리글·단위·주석·병합셀 의미가 유지되어야 한다. 인용에는 항·호·목, 별표 번호, 페이지/행, 원문 버전과 위치를 포함한다. 필수 근거 묶음을 다 담을 수 없으면 해당 쟁점의 추가 조회나 사람 검토로 전환한다.

### F09 — P0: 별표·공보·부칙 검증과 승인 결속이 약함

**코드 확인.** 별표 추출과 파일 저장은 있지만 전문에 합쳐진 텍스트와 별표 원본 파일 사이의 구조화된 연결 목록이 없다. 공보 승인은 URL·체크 항목·검토 메모를 받는 방식이며 공보 내용을 자동으로 확보·대조한 증거는 아니다. 승인 때 관련 자료에 검증·별표·연혁 완료 표시가 함께 적용된다.

**합성 재현.** 본문과 주요 메타데이터가 같고 `rawRef`만 달라지면 기존 검증 상태가 유지된다. 원본 바이너리만 바뀌고 추출 텍스트가 동일한 별표 변경도 이 식별 방식으로 충분히 구별하지 못한다.

**보완:** 법령 버전 → 조문/부칙 → 별표 → 원본 파일 → 추출 결과 → 대조 기록의 연결 목록을 둔다. 원본 파일 해시와 추출 텍스트 해시, 추출기 버전, 실패/잘림/표 검증 상태를 분리한다. 검토자는 대상별 확인 결과와 근거 위치를 기록하고 승인 범위를 명시한다. 공포 개정문과 시행 시점의 통합 전문을 구별한다. 관련 원본·파싱 결과·누락 목록이 바뀌면 해당 승인을 재검증한다.

### F10 — P1: 국민신문고·회신·파일 자료가 결과 근거까지 연결되지 않음

**코드 확인.** 공개 민원정책 Q&A API 전용 어댑터·설정·자료형·수집 경로는 아직 없다. 현행 국민신문고 연결 상태는 별도의 승인 기반 웹 자동화 경로다. 두 경로를 같은 허가 상태로 묶으면 안 된다. CSV는 현재 사용자 문서 업로드 지원 형식에 없다.

**합성 재현.** 업로드 문서는 모델 입력에 전달되지만 최종 인용 검증은 법규 evidence 목록만 조회한다. 별도 문서 ID를 인용해도 원문 검증을 통과하지 못한다. 첨부 문서의 지역 메타데이터도 모델 입력 문서 항목에 전달되지 않는다.

**보완:** 공개 Q&A API, 공개 파일, 사용자가 보유한 개인 회신을 별도 자료원으로 등록한다. 공개 API 키 저장·목록/상세·오류코드·페이지·총건수·갱신을 검증한다. 회신 기관·문서번호·회신일·등록일·관할·전제 사실·답변 원문을 보존한다. 첨부 자료에도 추적 가능한 인용을 허용하되 법적 근거와 참고자료의 역할을 명시한다. 다른 지역·다른 사실관계의 회신은 직접 적용 근거로 승격하지 않는다.

### F11 — P1: 검토 완전성이 ‘전국 1개 + 시·도 1개’에 묶여 있음

**합성 재현.** 국가 법령만 필요한 가상 사안도 조례가 없다는 누락 경고를 받는다. 현재 법규 검증은 국가법과 해당 시·도 조례가 모두 있어야 하고, 최근 확인 함수는 관련 자료원 수가 정확히 2개여야 한다. 위험물 시범 구조를 일반 EHS에 그대로 확장하기 어렵다.

**보완:** 쟁점마다 요구되는 자료 유형·법령 관계·관할·필수 사실을 정의하고 그 요구 목록 대비 완전성을 계산한다. ‘모든 조례 조회 완료’가 아니라 ‘이 쟁점에서 요구한 조회 계획의 완료’로 표시한다. 전체 자료 부족 때 규칙 판정을 막는 기존 장치는 유지한다. 쟁점 독립성과 공통 의존성 검증이 완성된 후에만 독립 쟁점의 부분 완료를 허용한다.

### F12 — P1: 갱신과 재검토의 영향 범위가 좁음

**합성 재현.** 기존에 인용한 출처의 버전 변경은 재검토 표시 대상이지만, 새 출처 ID의 법규 추가나 규칙만의 변경은 기존 검토를 표시하지 않는다. 원문 변경이 해당 기준일과 무관해도 같은 출처의 과거 결과 전체를 표시할 수 있어 과도한 경고도 가능하다.

**코드 확인.** 자료의 신선도와 공보 대조 승인 유효시간이 모두 24시간에 묶여 있다. 같은 원문을 다시 받았다는 이유만으로 전문가의 실질 판단을 매일 새로 받을지, 승인 근거가 바뀐 때만 받을지 정책이 분명해야 한다.

**보완:** 규칙·사실·자료원 목록·법령 관계·원본·관할·추출기 버전의 의존성을 저장한다. 새 의무 등장과 삭제/폐지/이관도 영향 이벤트로 처리한다. 자료원별 갱신 주기, 마지막 시도와 성공, 원문 최종 변경, 검증 시각을 분리한다. 승인 유효성은 근거 동일성·사건 범위·정책으로 판단하고, 신선도 부족은 별도 상태로 표시한다. 기준일에 영향 있는 사건만 재검토 대상으로 좁힌다.

### F13 — P0: 인증값 보호가 경로·형식별로 불일치

**이미 구현:** HTTPS, DPAPI, 기본 웹 요청 로그 비활성화, MCP stderr 폐기, 일부 URL 인증 매개변수 제거, 오류의 OC 문자열 치환.

**합성 재현:** 공개 링크 정리 함수에 `serviceKey`가 남는다. 가짜 OC에 `+`를 넣어 URL 인코딩된 오류를 만들면 원래 문자열 치환만으로 제거되지 않는다. 공개 검사도 URL의 대문자 `OC` 여부만 검사하며 모든 키 별칭·중첩 링크·오류 경로를 동일하게 검사하지 않는다. 이것은 가짜 문자열로 확인한 누락 경로이며 실제 인증값 유출을 확인한 것은 아니다.

**보완:** 요청 URL은 내부 전용으로 취급하고 인용용 URL은 자료원별 허용된 매개변수만으로 새로 만든다. 공통 인증정보 제거기를 오류·화면·MCP 응답·원문 메타데이터·내보내기·공개 검사에 적용한다. 인코딩/대소문자/별칭을 포함한 합성 비밀값으로 누출 시험을 한다. 새 서비스 키도 기존 보호 저장소를 사용하고 채팅이나 Git에 넣지 않는다.

### F14 — P1: 재현 가능한 검토 기록과 백업의 범위 불일치

**합성 재현·코드 확인.** 백업에는 법규 추출문과 사용자 문서 원본이 들어가지만 `legal-raw`·`legal-attachments` 파일, 감사 기록과 상세 승인 기록은 포함되지 않는다. 복원 시 승인을 해제하는 동작은 적절하지만, 무엇을 대조했는지 재검토할 원본까지 복구되는 것은 아니다. 공개 번들의 `rawRef`도 소비하는 컴퓨터에 해당 파일이 있다는 보장이 없다.

사용자 자료는 검토에 ID로 연결되고 모델에 보낸 원본/발췌 스냅샷이 검토 결과에 저장되지 않는다. 문서를 삭제하면 과거 검토의 사실 출처를 다시 확인하기 어렵다. 결과의 규칙 버전은 고정 문자열이고 실제 평가한 규칙 집합·프롬프트·추출기 버전의 전체 기록이 없다.

**보완:** 사건별 근거 목록, 원본과 발췌, 사용한 규칙 집합·계산·확인 사실·승인 기록·모델/프롬프트 버전을 묶는다. 백업에서 인증값은 계속 제외하되 검토 증거와 승인 이력은 감사 자료로 보존하고, 복원 후 운영 승인 상태는 별도로 재검증한다. 문서 보존/삭제 시 과거 검토 영향도 표시한다. 원본이 없는 공개 자료는 원문 접근 가능 여부를 명시한다.

### F15 — P1: 자료 보완 후 재검토의 연결이 약함

**코드 확인.** 추가 답변으로 재실행하면 기존 요청에 답변만 합친 새 검토가 만들어진다. 이 경로에서는 원래 문서 목록이 유지되어 새로 올린 자료가 자동으로 포함되지 않는다. 이전 검토 ID와의 관계도 데이터에 없다. 별도 새 검토 화면에서 문서를 선택하는 경로와 구분해야 한다.

**보완:** 사건 ID와 검토 회차/부모 검토 ID, 보완 질문 ID, 변경 사실과 추가 자료를 저장한다. 보완 화면에서 새 문서를 연결하고 변경 범위를 확인한 뒤 재실행한다. 지역·기준일·물질·구역 변경 시 기존 계산과 예외 확인의 유효성을 다시 판단한다. 단순 비어 있지 않은 답변을 이유로 미해결 질문을 닫지 않는다.

### F16 — P1: 자료 종류와 법적 역할을 충분히 구분하지 않음

**코드 확인.** 행정규칙 수집 결과가 일반 `law` 종류로 저장된다. 자료형에는 법규·회신·문서 등의 큰 구분만 있고 제정 주체, 문서 종류, 법적 역할, 위임 근거, 버전 관계의 별도 구조가 없다.

**보완:** 법률·명령·조례·규칙·행정규칙·해석례·회신·기술지침·현황을 구분하되 종류만으로 법적 효력을 일률 결정하지 않는다. 위임/인용/준용/예외/개정/폐지를 서로 다른 관계로 저장한다. 관계는 공식 구조화 데이터·원문 확인·모델 추정 등 확인 수준을 갖는다. 충돌은 단순 순위로 자동 해소하지 말고 위임 범위·시점·특별 규정 등을 검토할 쟁점으로 남긴다.

### F17 — P1/P2: 장시간 수집·실패 복구와 운영 관찰 설계

**이미 구현:** 요청 재시도·시간 제한, 페이지 총건수/중복 확인, 출처 단위 저장 트랜잭션, 실패 시 이전 자료 보존, 실행 중 변경 작업 제한, 재시작 시 중단된 검토 실패 표시, 예약 수집 실패를 작업 실패로 표시하는 경로.

**보완:** 출처별 호출 한도와 재시도 가능 오류, 재시도 간격, 중간 저장 지점, 작업 재개·취소, 동일 작업 중복 방지, 불완전 수집의 승격 조건을 정의한다. 조회 실패와 AI 설명 실패를 분리해 확보한 근거를 계속 검토할 수 있게 한다. 출처 등록 목록과 활성화 상태를 일반화해 Q&A나 새 법령 분야를 추가할 수 있게 한다. 자료 증가에 따라 모든 원문/보고서를 매번 읽는 검색·변경 검사 경로는 인덱스·의존성 조회로 전환하고 보관 용량을 관리한다. 실제 예약 실행 관측과 알림 정책은 별도 운영 검증이다.

### F18 — P1: 화면·내보내기·품질평가가 같은 결론을 보장해야 함

**코드 확인.** Markdown 결과는 기준일·미확인 범위·버전·재검토 표시가 있지만 CSV는 분류·결론·조치·URL 중심이라 이런 맥락이 빠진다. 파일로 전달된 결과가 현재 유효한 확정 판단으로 오해될 수 있다.

**보완:** 화면·Markdown·CSV에 검토 ID/회차, 기준일·행위일·관할, 근거 버전, 판정 상태·범위, 미확인 내용, 재검토 필요를 일관되게 담는다. 근거 없는 자동 조치나 실제 신고 제출은 검토 결과 생성과 분리한다. AI 전송 시 질문·선택 자료 범위 안내는 기존 기반을 유지하고 보완 검토에서 추가 자료의 전송 범위도 확인할 수 있게 한다.

품질 평가는 전문가 확인 사례의 필수 근거 검색 누락, 관련성, 시간·관할 정확성, 인용 정확성, 예외 판정, 위반 오탐과 미탐, 보류 비율을 나눠 측정한다. 모든 결과를 보류해서 오탐만 낮추는 방식은 목표 달성이 아니다. 자료 부족 사례를 정상 사례에 포함해 특이도를 계산하지 않는다. 아직 실제 특이도나 법률 정확도 수치를 주장할 수 없다.

| 규칙 조건 아니요 → 리스크 없음 | 불충족 / 적용 제외 / 미평가 / 오류를 먼저 구분 | 평가하지 못한 사안을 정상으로 표시하지 않기 위해 |
| 사람 검토 → 승인 규칙 적용 | 검토 범위·근거·예외·시험 사례 확인 → 버전 승인 → 같은 사건 재평가 | 승인만으로 미확인 사실이 해결되는 것은 아니기 때문 |
| 새 자료 → 재검토 | 법령·첨부·규칙·사실·관할·자료원 변경 → 영향 분석 → 해당 회차 재검토 | 새 의무와 규칙 변경도 찾아야 하기 때문 |

‘추가 자료 필요’와 ‘사람 판단 필요’는 한 사건에서 동시에 발생할 수 있다. 내부적으로 미해결 사유 목록을 유지하고 쟁점마다 주 분류를 표시한다. 법규 검토의 완료, 데이터 조회의 완료, 전문가 검증 완료도 서로 다른 상태여야 한다.

## 6. 구현 순서와 완료 조건

1. **판정과 인증정보 보호부터 보강:** 사실 상태, 평가 상태, 단정 문장 통제, 공통 인증정보 제거. 합성 불명 답변·미평가·가짜 인증 문자열 시험이 기대한 안전한 결과를 내야 한다.
2. **시간·관할·원본·인용 데이터 구조:** 시·군·구, 조문별 시행, 별표/부칙 목록, 첨부 원본 해시, 자료 역할, 쟁점별 요구 목록. 기존 자료를 삭제하지 않고 스키마를 이행하며 불명 정보는 불명으로 유지한다.
3. **자연어 조회 계획과 선택 자료원 연결:** 지원 범위를 분류하고 법령·조례 관계를 추적한다. 발급된 공개 Q&A 키를 보호 저장해 API 실응답을 검증한다. 사용하기로 확정한 자료만 활성화한다. 이때 국법뿐인 쟁점과 지방 조례가 필요한 쟁점을 구별해야 한다.
4. **검토와 재검토 연결:** 보완 자료 선택, 검토 회차, 조건·예외 계산, 전문가 승인 근거, 변경 영향과 원본 포함 백업, 동일한 내보내기 상태를 완성한다.
5. **화성시 소량위험물 시범 검증:** 실제 확인된 원문과 전문가 판정으로 정상·위반·경계·예외·자료 부족 사례를 시험한다. 범위를 명시한 승인 규칙부터 운영하고 이후 MSDS·폐기물로 확장한다.

API 키 추가 발급이 이 모든 작업의 선행조건은 아니다. 첫 두 단계와 조회 계획·시험 구성은 기존 인증정보를 다시 요구하지 않고 진행할 수 있다.

## 7. 시범 운영 전 인수 시험

- 법 이름을 쓰지 않은 자연어 질문에서 필요한 법령·조례와 핵심 예외를 찾는다.
- 지원 범위 밖 질문은 위험물 자료로 억지 해석하지 않는다.
- 화성시 입력이 다른 시·군·구 규칙으로 대체되지 않는다.
- 과거/현재/미래 시행, 조문별 시행 차이와 경과조치를 구별한다.
- 별표의 수치·단위·머리글·주석이 원본과 일치한다.
- 원본만 바뀐 첨부도 승인과 재검토에 반영한다.
- 조회 0건, 인증 오류, 한도, 일부 누락, 캐시 사용을 구분한다.
- 관련 없는 회신과 다른 지역 회신이 직접 근거가 되지 않는다.
- 업로드한 회신을 참고자료로 인용하고 원문 위치를 재확인할 수 있다.
- ‘확인 예정’·‘자료 없음’·‘아마’가 확인된 사실로 승격되지 않는다.
- 수량/단위/합산 구역/허가 사실을 확인하고 복합 조건을 평가한다.
- 규칙 불충족·예외 적용·규칙 없음·자료 부족을 서로 구분한다.
- 사람 검토 상태에 확정 위반 문장이나 근거 없는 시정 지시가 남지 않는다.
- 추가 문서를 포함한 보완 검토가 이전 회차와 연결된다.
- 새 법규·규칙 철회·예외 변경이 영향받는 과거 검토를 표시한다.
- 기준일에 영향 없는 변경으로 모든 과거 검토가 불필요하게 보류되지 않는다.
- 가짜 인증값의 인코딩·대소문자 변형이 오류·링크·보고서·공개 번들에 남지 않는다.
- 백업을 별도 빈 DB에 복원해 법규 원본·별표·사용자 문서·검토 이력을 재확인한다. 인증값은 복원하지 않는다.
- 화면·CSV·Markdown의 기준일·검증 범위·재검토 표시가 일치한다.
- 장애 후 확보한 근거를 유지하고 미완료를 완료로 표시하지 않는다.
