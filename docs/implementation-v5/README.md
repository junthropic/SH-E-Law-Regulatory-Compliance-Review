## 2. 새 실제 연결과 모의 범위

추가한 backend 경로는 다음과 같다.

1. 공식 페이지의 파일 링크/파일 식별자 발견 → 정확한 host/path/file ID 허용 → 기존 고정 IP downloader → 암호 원본 → 제한된 자원 권한의 별도 파서 프로세스 → 암호 추출 결과.
2. v4 실제 worker/adapter/원문 capture → A07/A08 제공 필드 후보 → 버전을 확인한 수동 보완 → 독립 합성 검토 → 기존 UI의 검토와 관리용 증빙 export 연결.
3. 동일 DB snapshot의 기존 백업과 v4 보호 계층 → 통합 암호 묶음 → 미공개 복원 세대 → 원본·참조 검증 → 세대 포인터 공개.
4. 실제 공공 API transport의 전송 admission → 권한 재확인·진행 중 철회 취소 → 결과 상태 기록.
5. v3 작업/단위/이력과 검토 trace의 암호 복사 → 해시 대조 → 이관 marker. 원래 평문은 삭제하지 않는다.

외부 API 응답은 합성이다. 내부 서비스는 mock으로 대체하지 않았다. 공식 공개 문서 취득은 무인증 조사 경로다. 실제 키를 사용하는 API 호출은 0회다.

## 6. S2 제공 필드와 사실 확인의 한계

A07의 `brNo`와 A08의 `brno`를 별도 필드로 처리한다. 선행 0을 보존하고 숫자형으로 바뀐 사업자번호나 마스킹 값을 완전한 식별자로 복구하지 않는다. 같은 사업자번호도 같은 시설을 증명하지 않는다.

허가번호·처리용량·현재 재고·안정적인 시설 ID는 제공 필드로 만들지 않았다. 누락·null·빈 문자열·0을 구분한다. A08의 통합 수신일은 관할기관 접수일이 아니며 처분일/시작일/종료일만으로 현재 처분 효력을 확정하지 않는다.

수동 보완은 예상 버전이 맞아야 저장된다. 원천을 새로 연결하면 수동 값은 보존하되 기존 검토를 해제한다. 독립 검토는 후보와 미확인 사항 대조이며 허가·용량·현장 사실의 법적 승인이 아니다. `source_missing`, `identity_conflict`, `contract_missing`, `capacity_unknown`, `sanction_effect_unknown`은 관리 trace에 남는다. 사용자용 분류는 **추가 자료 필요**다. ‘허가 서류 미제공’을 ‘무허가’로 바꾸지 않는다.

## 7. 통합 복원 범위와 한계

[backup-manifest.json](backup-manifest.json)은 실제 합성 복원 시험의 포함 목록·원본 해시/길이·제외·누락이다. 연결된 legacy 검토·문서·원본, v2 버전·정책·승인 이력, v3 작업, v4 암호 자료·파생·승인 이력, 지정된 v5 자료를 한 snapshot 기준으로 포함한다. 원본 파일은 참조 해시를 대조하며 수집 도중 삭제/변경으로 불일치하면 실패한다.

복원 후 작업은 paused, lease는 무효, 외부 전송은 deny, 현재 승인은 재검토 상태다. legacy/v2/v3/v4를 새 Store로 읽었다. 미공개 세대에서 오류가 발생하면 현재 세대 포인터를 만들지 않는다. 실제 별도 복원 프로세스를 종료시킨 시험에서 기존 세대가 노출되지 않았고, 죽은 프로세스의 동일 archive 잠금만 복구해 재복원했다. 사용자 프로세스를 종료하지 않았다.

소유권이 연결되지 않은 legacy 자료, 미분류 테이블, 누락 원본, 별도 공개 자료 캐시가 있으면 전체 복구 완료가 아니다. 키는 백업에 넣지 않는다. 키가 없거나 다른 버전이면 복원을 중단한다. 실제 power-loss·디스크 부족·모든 동시 파일 변경·Windows ACL/키 회전·전체 경로 alias 조합은 미검증이다. 중단된 미공개 세대는 자동 삭제하지 않고 보존한다. 운영 파일을 복원하거나 교체하지 않았다. [SQLite snapshot 설명](https://www.sqlite.org/backup.html)을 참고했다.

## 8. 전송 admission과 철회

같은 SQLite의 짧은 `BEGIN IMMEDIATE` 안에서 권한 읽기와 전송 intent를 기록한다. v4 revoke는 같은 DB에 쓰므로 **revoke commit이 admission보다 먼저이면 새 admission이 거절**된다. 실제 공공 API 호출 경로에 연결했고 별도 프로세스의 철회도 시험했다.

admission 이후에는 시작 전 재확인과 25ms 간격 확인으로 대기/진행 중 요청을 가능한 범위에서 취소한다. 취소는 자동 재시도 가능한 네트워크 오류로 처리하지 않는다. 네트워크 대기를 DB write lock 안에서 수행하지 않는다. 요청의 실제 첫 송신 byte는 관측하지 못하므로 `unobserved`로 남긴다. 응답 bytes 관측과 구분하며 이미 송신한 bytes의 회수를 보장하지 않는다.

AI/intake/MCP의 기존 v4 검사와 legacy v3 fallback 전체를 이번에 대체한 것은 아니다. 답변 재사용·모든 export의 자동 parent 해석도 남았다. 따라서 B-egress는 미완료다. 일반 앱/시험 앱과 실제 영역/가상 영역 조합 4개에서도 관리 권한은 명시적으로 제공해야 접근된다.

## 9. 법령 profile과 충돌

공식 PDF의 수탁능력 확인(1·2·3란), 수탁 확인(1·2·4란), 병행 작성(1~4란)을 분리했다. 연간량/시간당량/부피 환산에는 각각 필요한 근거를 요구하고, 전일 재고 및 공식 작성방법의 음수를 보존한다. 이 산식을 일반적인 시설 적합성 판정으로 사용하지 않는다.

서식 제2쪽의 제17조 인용과 현행 제18조 경로의 충돌을 남겼다. 자료를 임의 교정하거나 의무 범위를 줄이지 않았다. 고시 2024-76 전문과 부칙, 법21374 및 규칙470 전문을 확보했다. 해당 규칙470의 부칙은 2026-06-01 시행 문구로 확인됐지만 다른 버전과 모든 하위 경로를 전수 승인한 것은 아니다. 조회 기준일과 평가 실시일을 별도로 보관하고 제36조 적용례를 평가 사건에 연결한다. 과거 기록 조문과 현행 기록 조문을 구분하며 소급 위반을 만들지 않는다.

5월31일 적용본으로 제시된 MST271485의 공개 본문 조회는 오류 문서가 반환되어 **미확보**다. 2026-461 행정예고를 시행 규칙으로 활성화하지 않는다. 후속 확정 공표 확인, 폐기물 하위 정의·위임·제외 범위 전개, 고시/규칙 충돌의 전문가 판단은 남았다. 정책은 원래 43+추가 2를 유지하고 실제 전문가 승인·활성화는 0이다.

## 10. 유지한 gate와 다음 조건

[release-gate.json](release-gate.json)의 12개 ID와 기존 상태를 보존했다. 새 증거가 생긴 부분만 구체화했다. 다음 우선순위는 정부 pin 경로의 정상 원문 응답 확인, 남은 원문/operation 표본, S2의 실제 허가·시설·능력 근거, 전송 경로 전수 parent 연결, 백업 장애 매트릭스, 보호 이관의 재개 검증이다. 후속 정책 순서는 교육 5 → 안전관리자 6 → 안전검사 5 → 잔여이며 원래 미구현 후보를 완료로 바꾸지 않았다.

실제 사업장 검증은 자료가 없어서 대기한다. 운영 연결·실제 키 사용·배포·재시작·법적 규칙 활성화는 이번 요청에서 금지되었으므로 실행하지 않았다.
