# tests/ — 자동 시험

## 맡은 일
vitest 시험(`*.test.ts`)과 도우미(`helpers.ts`, `*-fixture.ts`, `fixed-now.preload.mjs`, `date-matrix.mjs`, `fixtures/`). 서버·공용 코드의 규칙을 지킨다: 검토 판단, 근거 빈틈, 인용 검증, 접근 검문, 암호화, 외부 통신 가드, 백업·복원, 화면 잠금, 패키지 스캔.

## 맡지 않는 일
- 실제 외부 서비스(법제처, 공공 API, AI)를 부르는 시험. 외부 응답은 합성 값으로 흉내 낸다.
- 사용자의 `.local` 데이터를 읽거나 쓰는 일.
- `work/` 아래 격리 빌드 복사본 시험. 시험 범위는 `tests/**/*.test.ts`뿐이다.

## 반드시 지키는 것
- 시계는 고정 시계를 쓴다(`fixed-now.preload.mjs`, `SHE_TEST_NOW`, `SHE_TEST_CLOCK_OFFSET_MS`는 `vitest.config.ts`가 계산해 자식 프로세스까지 같게 넘긴다). `new Date()`의 실제 현재 시각에 기대지 않는다. 날짜는 `koreaDate()`.
- 근거의 `fetchedAt`은 현재 시계 기준 상대 값으로 만든다. 24시간이 지난 고정 값은 하루 뒤 시험을 깨뜨린다.
- 데이터 폴더는 임시 폴더를 만들고 시험 뒤에 지운다.
- 키·토큰·이메일·사용자 경로는 합성 값만 쓴다. 실제 값을 고정 자료에 넣지 않는다.
- 후보 계층 시험은 `synthetic: true`인 가짜 사용자만 쓴다.
- 판단 구조를 바꾸면 `clear_risk`가 기본 경로에서 나오지 않는 것을 확인하는 시험을 유지한다.
- 일부 시험은 저장소의 문서 폴더에 있는 고정 자료(공문 원본, 계약 표, 잠금 기준 목록, 설치 시험 결과)를 읽는다. 그 파일을 옮기거나 지우기 전에 읽는 시험을 먼저 찾는다.
- 화면 잠금 시험(`v8-ui-freeze`)이 실패하면 화면 파일이 바뀐 것이다. 시험을 고치지 말고 사용자 승인 여부를 먼저 확인한다.
- 건너뛴 시험과 외부 서비스에 의존하는 시험은 결과 보고에서 따로 적는다.

## 구현 방식
- 파일 이름 `v2-`~`v8-`은 시험이 지키는 단계다. 새 시험은 지키려는 동작에 가까운 이름의 파일에 넣는다.
- Windows에서 시간 초과가 간헐적으로 난다. 실패한 CI 작업만 다시 돌리고, 같은 시험이 반복해서 실패할 때만 코드를 의심한다.
